---
title: "Mevcut Kullanıcı (/me)"
description: "Aktif kullanıcının tenant, bayi, rol ve açık modül bağlamı."
---

`GET /me`; çağıranın **kim olduğunu**, **hangi tenant'a ve bayiye bağlı olduğunu**, **hangi rollere sahip olduğunu** ve **hangi modüllerin açık olduğunu** tek istekte döner. Panellerin giriş sonrası yaptığı kanonik çağrıdır; entegrasyonlar da hangi modüllerin kullanılabilir olduğunu öğrenmek için kullanabilir.

## Endpoint

```http
GET /api/v1/me
```

Bearer access token gerektirir.

```bash
curl https://identity.payven.com.tr/api/v1/me \
  -H "Authorization: Bearer eyJhbGciOiJSUzI1NiI..."
```

## Yanıt

`200 OK`:

```json
{

    "id":       "9f3d2b8e-...",
    "username": "ayse@example.com",
    "email":    "ayse@example.com",
    "name":     "Ayşe Yılmaz"
  },
  "tenant": {
    "id":           "1a2b3c4d-...",
    "slug":         "payven",
    "display_name": "Payven A.Ş.",
    "aliases":      [],
    "brand_name":   "Payven",
    "require_otp_for_login": false
  },
  "merchant": {
    "id":          "3fa85f64-...",
    "external_id": "M-IST-001",
    "name":        "Acme E-Ticaret",
    "parent_id":   null,
    "status":      "approved",
    "environment": "live"
  },
  "home_merchant": { "id": "3fa85f64-...", "external_id": "M-IST-001", "name": "Acme E-Ticaret", "parent_id": null, "status": "approved", "environment": "live" },
  "roles": ["merchant-admin"],
  "features": [
    {
      "code":         "sanalpos",
      "display_name": "Sanal POS",
      "base_path":    "/sanalpos",
      "is_active":    true,
      "permissions":  ["CanViewTransactions", "CanRequestRefund"],
      "nav_items": [
        { "id": "transactions", "name": "İşlemler", "href": "/transactions", "required_permission": "CanViewTransactions", "display_order": 100 }
      ]
    }
  ],
  "enabled_feature_codes": ["sanalpos", "fraud", "fraud.sanalpos"]
}
```

| Alan | Açıklama |
|---|---|
| `user` | Kullanıcı kimliği: `id`, `username`, `email`, `name` |
| `tenant` | Aktif tenant: `id`, `slug`, `display_name`, `aliases`, marka alanları (`brand_*`), `require_otp_for_login` |
| `merchant` | Kullanıcının bayisi. `status`: `pending` / `approved` / `rejected`; `environment`: `sandbox` / `live`; `parent_id`: alt bayide üst bayi. `X-Merchant-Id` başlığını **uygulamaz** (aşağıya bakın) |
| `home_merchant` | Kullanıcının **kendi** bayisi (yalnız token'dan). Tenant kapsamlı kullanıcıda `null` |
| `roles` | Çağıranın rolleri |
| `features[]` | Tenant'ta açık **modüller**; her biri için çağıranın rollerinden çıkan izin adları (`permissions`) ve bu izinlere göre filtrelenmiş menü öğeleri (`nav_items`) |
| `enabled_feature_codes` | Tenant'ın etkin **tüm** feature kodları (alt-feature'lar dahil: `fraud.sanalpos`, `fraud.alerts.review` ...). Modül listesi (`features`) yalnız ana modülleri içerir |

`permissions` değerleri Identity izin kataloğundaki adlardır ve Portal'daki yetki denetimiyle birebir aynıdır; bayi kapsamlı rollerde izinler yalnız o bayinin verisi için geçerlidir.

<Note>
`/me` bir "kim olduğumu ve ne yapabileceğimi" ucudur; **hangi bayiye baktığınızı** istemcinin seçimi belirler. Bayi kapsamlı çağrılarda `X-Merchant-Id` (Guid) ve `X-External-Merchant-Id` başlıklarını diğer servislere gönderin; `/me` bu başlıkları yok sayar ve her zaman token'daki bayiyi döner.
</Note>

## Bayi listesi

Çok bayili (tenant / üst bayi) kullanıcılar için:

| Endpoint | Açıklama |
|---|---|
| `GET /api/v1/me/merchants` | Çağıranın erişebildiği bayilerin **sayfalı** listesi (`page`, `page_size`, `search_term`, `ids`). Öğe: `id`, `external_id`, `name` ... |
| `GET /api/v1/me/merchants/tree` | Kendi bayisi + alt bayileri iç içe **ağaç** (`root`, `total_count`). Tenant kapsamlı kullanıcıda `root: null` |
| `GET /api/v1/me/header` | Bayi seçici + gelen kutusu sayaçlarını tek yanıtta döner (panel başlığı için) |

Kapsam, çağıranın token'ındaki bayi ve rolüne göredir; seçili bayi başlığı listeyi daraltmaz.

## Plan ve kullanım

Tenant planı ayrı uçtan okunur: [`GET /me/plan`](/identity/auth/plan).

## Kullanım örnekleri

```javascript
const me = await fetch("/api/v1/me", { headers: auth }).then(r => r.json());

// Açık modüller
const modules = me.features.filter(f => f.is_active).map(f => f.code);
// → ["sanalpos", "para-transferi"]

// Alt-feature kontrolü (ör. fraud kural yönetimi açık mı?)
const rulesOpen = me.enabled_feature_codes.includes("fraud.rules.custom");

// İzin kontrolü
const sanalpos = me.features.find(f => f.code === "sanalpos");
const canRefund = sanalpos?.permissions.includes("CanRequestRefund");
```

## Hata yanıtları

| HTTP | Anlam |
|---|---|
| `401` | Token yok / geçersiz / süresi dolmuş ya da kullanıcı bağlamı çözülemedi |

## Alternatif: `/auth/{slug}/me`

`GET /api/v1/auth/{slug}/me` yalnızca Keycloak userinfo'sunu (kullanıcı adı, e-posta, ad, roller) döner; tenant, bayi ve modül bağlamı içermez. Entegrasyonlarda `GET /api/v1/me` tercih edin.
