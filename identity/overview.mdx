## Auth modeli

Identity OAuth 2.0 Client Credentials akışıyla çalışır: API anahtarınızın `client_id` + `client_secret` çiftiyle bir access token alır, sonraki tüm isteklerde (Identity dahil tüm ürün servisleri) `Authorization: Bearer <access_token>` gönderirsiniz.

```http
Authorization: Bearer eyJhbGciOiJSUzI1NiIs...
```

Token'ın hangi servislere geçerli olacağı **anahtarın API kapsamıyla** belirlenir (anahtar oluştururken seçtiğiniz `features`). Kapsamda olmayan servis `401 audience_invalid` döner. Kapsam seçimi: [Yeni API Anahtarı](/identity/api-keys/create).

Token nasıl alınır: [Kimlik Doğrulama](/documentation/concepts/authentication).

## Slug tabanlı oturum uçları

Token uçları tenant slug'ını URL'de taşır; slug size onboarding sırasında verilir.

```
POST /api/v1/auth/{slug}/token       # client_credentials
POST /api/v1/auth/{slug}/refresh
POST /api/v1/auth/{slug}/logout
GET  /api/v1/auth/{slug}/me          # yalnız userinfo (ham)
```

`/auth/{slug}/token` istek gövdesi: `client_id`, `client_secret`, isteğe bağlı `offline` (uzun ömürlü refresh token; yalnız "offline erişim" izni verilmiş anahtarlarda).

Token alırken anahtarın kendi kısıtları denetlenir:

| HTTP | `code` | Anlam |
|---|---|---|
| `400` | `client_credentials_required` | `client_id` / `client_secret` boş |
| `401` | `client_unauthorized` | Anahtar veya secret geçersiz; anahtar pasif ya da silinmiş |
| `401` | `api_key_expired` | Anahtarın `expires_at` tarihi geçti |
| `403` | `api_key_ip_not_allowed` | İstek `allowed_ips` listesi dışından geldi |

Hata yanıtı daima `PayvenProblemDetails` zarfıdır (`code`, `message`, `category`); bkz. [Hata Yönetimi](/documentation/concepts/errors).

## Genel sözleşme

- Tüm alanlar, query parametreleri ve enum değerleri **snake_case**; camelCase query `400` döner.
- Tarihler `+03:00` ofsetiyle döner; istekte ofsetsiz tarih UTC sayılır, bu yüzden ofseti her zaman yazın.
- Liste uçları (API anahtarları, webhook uçları, olaylar) sayfalıdır: `page`, `page_size`, yanıt `items`, `page`, `total_pages`, `total_count`, `has_previous_page`, `has_next_page`. Referans veri listeleri (banka, BIN, MCC, il, ilçe) **sayfasız düz dizidir**.
- Tutarlar kuruş (`long`) cinsindendir.

## Rol kapsamı

Rol adının önekine göre belirlenir: `tenant-*` roller tüm bayileri, diğer roller (`merchant-*`, bayiye özel roller) yalnızca kendi bayisini görür. Bayi kapsamlı bir anahtar `merchant-admin`, bayisiz (tenant geneli) anahtar `tenant-admin` rolü taşır.
