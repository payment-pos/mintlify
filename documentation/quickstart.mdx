Bu rehber, Payven'e entegre olacak bir geliştiricinin izleyeceği yolu sırayla gösterir. Tüm örnekler **test modunda** çalışır: gerçek kayıtlar yazılır, bankaya gidilmez, gerçek para hareketi olmaz.

| Adım | Ne yapılır | Nerede |
|---|---|---|
| 1 | İşyeri (bayi) açılır | İşyeri paneli başvurusu ya da `POST /merchants` |
| 2 | Test API anahtarı alınır | İşyeri paneli › Ayarlar › Entegrasyon |
| 3 | Access token alınır | `POST /auth/{slug}/token` |
| 4 | İlk ödeme yapılır | `POST /checkout/sessions` ya da `POST /payments` |
| 5 | Webhook kurulur | `POST /webhook-endpoints` |
| 6 | Hata, idempotency ve limitler ele alınır | [Hata Yönetimi](/documentation/concepts/errors) |
| 7 | Canlıya geçiş talep edilir | [Canlıya geçiş](#7-canliya-gecis) |

<Note>
**Adresler.** Örneklerde `identity.payven.com.tr` ve `vpos.payven.com.tr` kullanılır; alan adı kurulumunuza göre değişir. İşyeri paneli › Ayarlar › Entegrasyon ekranı kendi **API adresinizi** ve **Identity adresinizi** gösterir. **Test ve canlı aynı adrestedir**: ortamı adres değil, kullandığınız API anahtarı belirler.
</Note>

## 1. İşyeri (bayi) açın

Her ödeme bir işyeri adına yapılır. İki yoldan biriyle işyeri açılır:

<Tabs>
  <Tab title="İşyeri paneli başvurusu">
    İşyeri panelinin **Başvur** sayfasından başvuru yapılır; operatör onayından sonra işyeri **test modunda** açılır ve yetkiliye "parolanı belirle" bağlantısı gider. Başvuru formu İşyeri ve KYB belgelerini toplar; onay sürecini panel adım adım gösterir.
  </Tab>
  <Tab title="API ile (tenant yöneticisi)">
    Organizasyon (tenant) yöneticisi işyerini doğrudan açabilir. **`environment` göndermezseniz işyeri canlı açılır**; test modunda açmak için `sandbox` verin:

    ```bash
    curl -X POST https://identity.payven.com.tr/api/v1/merchants \
      -H "Authorization: Bearer $ADMIN_TOKEN" \
      -H "Content-Type: application/json" \
      -d '{
        "name":        "Acme Online",
        "legal_name":  "Acme Online Ticaret A.Ş.",
        "tax_id":      "1234567890",
        "external_id": "ACME-001",
        "email":       "finans@acme.example",
        "environment": "sandbox"
      }'
    ```

    Yanıttaki `id` (UUID) ve sizin verdiğiniz `external_id` bayiyi tanımlar. Açılışta bayiye otomatik bir **"Test anahtarı"** oluşturulur.
  </Tab>
</Tabs>

Hesap, işyeri ve anahtar ilişkisi için: [Hesap Yapısı](/documentation/account-model).

## 2. Test API anahtarınızı alın

İşyeri paneli › **Ayarlar › Entegrasyon** ekranında bayinin anahtarları listelenir. Test anahtarının `client_id` değeri `pvk-<kısa-ad>-test-<kod>` biçimindedir; gizli değeri (`client_secret`) test anahtarlarında **Göster** ile her zaman görülebilir. Yeni anahtarı işletme yöneticisi **Anahtar oluştur** ile üretir.

API ile üretmek isterseniz (işletme yöneticisi, kapsam token'dan gelir):

```bash
curl -X POST https://identity.payven.com.tr/api/v1/merchants/me/api-keys \
  -H "Authorization: Bearer $MERCHANT_ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "display_name": "Sunucu - test",
    "environment":  "test",
    "features":     ["sanalpos", "merchant"]
  }'
```

Yanıttaki `secret` alanı **yalnız bir kez** döner; `api_key.keycloak_client_id` ise `client_id` değeridir. Ortam (`test` / `live`) anahtar oluşturulurken seçilir ve sonradan değişmez. `features` anahtarın erişebileceği ürünleri belirler; seçilebilir değerler `GET /merchants/me/api-keys/assignable-scopes` ile listelenir.

<Warning>
`client_secret` yalnız sunucu tarafında tutulur; tarayıcıya, mobil uygulamaya ya da repoya girmez. Bkz. [API Anahtarı En İyi Uygulamaları](/documentation/security/api-key-best-practices).
</Warning>

## 3. Access token alın

`client_id` + `client_secret` ile Identity'den OAuth 2.0 `client_credentials` token'ı alınır. URL'deki `payven`, **tenant kısa adınızdır** (onboarding sırasında verilir).

<CodeGroup>
```bash cURL
curl https://identity.payven.com.tr/api/v1/auth/payven/token \
  -H "Content-Type: application/json" \
  -d '{
    "client_id":     "pvk-payven-test-a1b2c3d4",
    "client_secret": "YOUR_CLIENT_SECRET"
  }'
```

```javascript Node.js
const tokenRes = await fetch(
  "https://identity.payven.com.tr/api/v1/auth/payven/token",
  {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      client_id: process.env.PAYVEN_CLIENT_ID,
      client_secret: process.env.PAYVEN_CLIENT_SECRET,
    }),
  },
);
const { token } = await tokenRes.json(); // yanıt { token, challenge } zarfında
const accessToken = token.access_token;
```

```python Python
import httpx, os

token_res = httpx.post(
    "https://identity.payven.com.tr/api/v1/auth/payven/token",
    json={
        "client_id":     os.environ["PAYVEN_CLIENT_ID"],
        "client_secret": os.environ["PAYVEN_CLIENT_SECRET"],
    },
)
access_token = token_res.json()["token"]["access_token"]  # yanıt {token, challenge} zarfında
```
</CodeGroup>

Yanıt:

```json
{
  "token": {
    "access_token":       "eyJhbGciOiJSUzI1NiI...",
    "refresh_token":      "eyJhbGciOiJIUzI1NiI...",
    "expires_in":         300,
    "refresh_expires_in": 0,
    "token_type":         "Bearer",
    "scope":              "openid profile email"
  },
  "challenge": null
}
```

**Access token 5 dakika geçerlidir.** Cache'leyin ve süresi dolmadan yenileyin; her istekte yeni token almayın. Hazır istemci kodu: [Kimlik Doğrulama](/documentation/concepts/authentication#kod-ornekleri-auto-refresh).

<Note>
**Bayi bağlamı.** Bayiye bağlı bir anahtarla bayi kimliği token'dan çözülür; ek header gerekmez. Organizasyon geneli bir anahtarla ödeme gibi işlem yapan uçlarda `X-Merchant-Id` (UUID) ya da `X-External-Merchant-Id` header'ı **zorunludur**; yoksa `400 merchant_context_missing` döner.
</Note>

## 4. İlk ödemeyi yapın

### Önerilen yol: Hosted Checkout

Kart bilgisi Payven'in barındırdığı ödeme sayfasında girilir; kart verisi sunucunuza hiç uğramaz (PCI kapsamı en düşük). Tutar **kuruş** cinsindendir: `15000` = 150,00 ₺.

<CodeGroup>
```bash cURL
curl -X POST https://vpos.payven.com.tr/api/v1/checkout/sessions \
  -H "Authorization: Bearer $TOKEN" \
  -H "Idempotency-Key: ORDER-1001" \
  -H "Content-Type: application/json" \
  -d '{
    "amount":      15000,
    "currency":    "TRY",
    "external_id": "ORDER-1001",
    "description": "Sipariş ORDER-1001",
    "success_url": "https://magazaniz.com/odeme/basarili",
    "cancel_url":  "https://magazaniz.com/odeme/iptal"
  }'
```

```javascript Node.js
const res = await fetch("https://vpos.payven.com.tr/api/v1/checkout/sessions", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${accessToken}`,
    "Idempotency-Key": "ORDER-1001",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    amount: 15000,
    currency: "TRY",
    external_id: "ORDER-1001",
    description: "Sipariş ORDER-1001",
    success_url: "https://magazaniz.com/odeme/basarili",
    cancel_url: "https://magazaniz.com/odeme/iptal",
  }),
});
const session = await res.json();
// müşteriyi session.checkout_url adresine yönlendirin
```

```python Python
res = httpx.post(
    "https://vpos.payven.com.tr/api/v1/checkout/sessions",
    headers={
        "Authorization":   f"Bearer {access_token}",
        "Idempotency-Key": "ORDER-1001",
    },
    json={
        "amount":      15000,
        "currency":    "TRY",
        "external_id": "ORDER-1001",
        "description": "Sipariş ORDER-1001",
        "success_url": "https://magazaniz.com/odeme/basarili",
        "cancel_url":  "https://magazaniz.com/odeme/iptal",
    },
)
session = res.json()
```
</CodeGroup>

Yanıt (`201 Created`):

```json
{
  "session_id":         "9f3d2b8e4c1a4d7b8e3f5c129a7b4c8d",
  "checkout_url":       "https://vpos.payven.com.tr/s/AbC123",
  "checkout_page_url":  "https://vpos.payven.com.tr/checkout/...?session=9f3d2b8e4c1a4d7b8e3f5c129a7b4c8d",
  "expires_at":         "2026-10-17T15:04:05+03:00",
  "opened_ttl_minutes": 30
}
```

Müşteriyi `checkout_url` adresine yönlendirin (`checkout_url` kısa adrestir, `checkout_page_url` doğrudan adrestir). Test modunda ödeme sayfasında **geçerli biçimde herhangi bir kart numarası** girin (örneğin `4111 1111 1111 1111`, ileri bir son kullanma tarihi, herhangi 3 haneli CVV); 3D Secure ekranında **herhangi 6 haneli kodu** yazın. Ödeme başarıyla tamamlanır ve ödemeler listesinde test işlemi olarak görünür. Belirli senaryolar (ret, yetersiz bakiye) için kayıtlı test kartları kullanılır: [Test Kartları](/sanal-pos/test/test-cards).

### Doğrudan API (Non-3D)

Kart bilgisini kendi sunucunuzdan alıyorsanız `POST /payments` kullanılır. `external_id` **zorunludur** (aynı sipariş için çift çekimi önleyen anahtardır).

```bash
curl -X POST https://vpos.payven.com.tr/api/v1/payments \
  -H "Authorization: Bearer $TOKEN" \
  -H "Idempotency-Key: ORDER-1002" \
  -H "Content-Type: application/json" \
  -d '{
    "external_id":    "ORDER-1002",
    "amount":         { "amount": 15000, "currency": "TRY" },
    "installment":    1,
    "operation_type": "sale",
    "card": {
      "holder_name":  "Test Kullanici",
      "number":       "4111111111111111",
      "expire_month": "12",
      "expire_year":  "2030",
      "cvv":          "123"
    }
  }'
```

Başarılı yanıt (`200 OK`, ilgili alanlar):

```json
{
  "transaction_id":        "8e3f5c12-9a7b-4c8d-bc4e-2c963f66afa6",
  "status":                "completed",
  "is_success":            true,
  "amount":                15000,
  "total_customer_amount": 15000,
  "interest_amount":       0,
  "currency":              "TRY",
  "extra_properties": {
    "processed_at":            "2026-10-16T15:04:05.123+03:00",
    "external_id":             "ORDER-1002",
    "auth_code":               "123456",
    "host_reference":          "PAYVEN-REF-789",
    "provider_transaction_id": "9f3d2b8e-..."
  }
}
```

`status: "completed"` ödemenin tamamlandığını gösterir. `transaction_id` değerini saklayın; sorgulama, iade ve webhook eşleştirmesinde kullanılır.

<Warning>
**Non-3D izni bayi bazındadır.** Bayinin en az bir aktif banka profilinde Non-3D açık değilse istek `422 PV_NON_3D_NOT_ALLOWED` ile reddedilir. Tüketici akışlarında 3D Secure ya da Hosted Checkout kullanın: [3D Secure](/sanal-pos/payments/3d-secure), [Hosted Checkout](/sanal-pos/payments/hosted-checkout).
</Warning>

Ödemeyi sorgulama:

```bash
curl https://vpos.payven.com.tr/api/v1/payments/8e3f5c12-9a7b-4c8d-bc4e-2c963f66afa6 \
  -H "Authorization: Bearer $TOKEN"
```

Alanların tamamı: [Payment Objesi](/sanal-pos/payment-object).

## 5. Webhook kurun

Tarayıcı tabanlı akışlarda (3DS, Hosted Checkout) müşteri sayfayı kapatabilir; sonucu güvenilir biçimde sunucunuz webhook ile öğrenir. **Tek uç tüm ürünlerin olaylarını alır.**

```bash
curl -X POST https://identity.payven.com.tr/api/v1/webhook-endpoints \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "url":            "https://your-domain.com/webhooks/payven",
    "enabled_events": ["sanalpos.payment.completed", "sanalpos.payment.failed", "sanalpos.payment.not_completed", "sanalpos.refund.completed"]
  }'
```

Yanıttaki `secret` (`whsec_...`) **yalnız bir kez** döner; saklayın. İsteğin Payven'den geldiğini `X-Payven-Signature` ile doğrulayın (HMAC-SHA256, [İmza Doğrulama](/sanal-pos/webhooks/signature)). Test anahtarıyla oluşan olaylar `livemode: false` taşır ve gerçek imzayla, gerçekten teslim edilir. Uç yönetimi, yeniden deneme ve olay kodları: [Webhook'lar](/documentation/concepts/webhooks).

<Note>
Uç yönetimi `CanManageWebhooks` yetkisi ister. İşyeri API'si kuruluysa aynı yol İşyeri API'si adresinde de çalışır; o adrese giden anahtarın **İşyeri API'si** kapsamı seçili olmalıdır (aksi halde `401 audience_invalid`).
</Note>

## 6. Hata, idempotency ve limitleri ele alın

- **Hata zarfı tektir** (`application/problem+json`): `code`, `message`, `category`, `param`, `correlation_id`. Kararı HTTP durum kodu ve `code` üzerinden verin: [Hata Yönetimi](/documentation/concepts/errors).
- **`Idempotency-Key`** gönderin; ağ hatasında aynı anahtarla tekrar denemek ikinci işlem oluşturmaz: [Idempotency](/documentation/concepts/idempotency).
- **429** alırsanız `Retry-After` kadar bekleyin: [Rate Limiting](/documentation/concepts/rate-limiting).
- Tarihler her zaman `+03:00` ile döner; istek tarafında offset'i açıkça yazın: [Tarih ve Zaman](/documentation/concepts/timestamps).

## 7. Canlıya geçiş

Test modundaki bayi canlıya kendiliğinden geçmez. Akış:

<Steps>
  <Step title="Entegrasyon kontrol listesini tamamlayın">
    İşyeri paneli › **Ayarlar › Entegrasyon** (ya da `GET /settings/integration`) şu maddeleri **test modundaki gerçek kayıtlardan** türetir: başarılı test ödemesi, başarısız ödeme senaryosu, iade testi (üçü zorunlu) ve webhook doğrulaması (isteğe bağlı).
  </Step>
  <Step title="Canlı geçiş talebi açın">
    Zorunlu maddeler tamamlanınca işletme yöneticisi **Canlıya geçiş talep et** der (`POST /settings/integration/live-requests`). Talep bayiyi canlıya almaz; operatör incelemesine düşer.
  </Step>
  <Step title="Operatör onayı">
    Onay verildiğinde bayinin ortamı `live` olur. Onaydan sonra istekler canlıdır; test kayıtları canlı listelerde görünmez.
  </Step>
  <Step title="Canlı anahtar üretin">
    `environment: "live"` ile yeni bir anahtar oluşturun ve secret'ı secret manager'a yazın (canlı anahtarın secret'ı yalnız oluşturulurken görünür). Test anahtarını koddan kaldırın.
  </Step>
</Steps>

Canlıya çıkmadan önce [Production Geçiş Kontrol Listesi](/documentation/security/go-live-checklist)'ni tamamlayın. Test verisini temizlemek için İşyeri panelindeki **Tüm test verilerini sil** kullanılır; canlı veri silinmez.

## Yardım

Bir adımda takılırsanız yanıttaki `X-Correlation-Id` header'ını (hata gövdesinde `correlation_id`) [destek ekibine](/resources/support) iletin.
