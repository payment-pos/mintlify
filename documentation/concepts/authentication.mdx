---

Payven API'leri **OAuth 2.0 Client Credentials** akışı ile çalışır. Backend'inizden Identity servisinden bir access token alır, ürün API'lerine `Authorization: Bearer <token>` header'ı ile istek atarsınız.

İki kısa adım:

1. **Token al** — `client_id` + `client_secret` ile Identity'den `access_token` iste.
2. **API'yi çağır** — `Authorization: Bearer <access_token>` header'ı ile anahtarınızın kapsadığı ürünlerin (Sanal POS, Para Transferi, Cüzdan, Identity ...) endpoint'lerini kullan.

Token süresi dolduğunda yenisini alır veya `refresh_token` ile yenilersin. Kod örnekleri bu döngüyü sizin için yönetir.

`client_id` değeri anahtarın ortamını taşır: `pvk-<kısa-ad>-test-<kod>` **test**, `pvk-<kısa-ad>-live-<kod>` **canlı** moddadır. Test anahtarıyla yapılan her istek test modunda işlenir ([Hesap Yapısı](/documentation/account-model#test-ve-canli-mod)). Anahtarı İşyeri paneli › Ayarlar › Entegrasyon ekranından ya da `POST /merchants/me/api-keys` ile oluşturursunuz.

## Akış (özet)

```mermaid
sequenceDiagram
    participant App as Sizin Backendiniz
    participant Id as Payven Identity
    participant API as Ürün API (Sanal POS / Para Transferi / ...)

    App->>Id: POST /auth/{slug}/token<br/>{ client_id, client_secret }
    Id-->>App: { token: { access_token, refresh_token, expires_in: 300, ... }, challenge: null }
    Note over App: access_token cache'le<br/>5 dakika geçerli

    App->>API: POST /payments<br/>Authorization: Bearer <access_token>
    API-->>App: 200 OK

    Note over App: 5dk sonra access_token<br/>expiry'sine yakın
    App->>Id: POST /auth/{slug}/refresh<br/>{ refresh_token }
    Id-->>App: { access_token (yeni), refresh_token (rotasyonlu) }
```

## 1. Adım — Token al

```http
POST https://identity.payven.com.tr/api/v1/auth/{slug}/token
Content-Type: application/json
```

`{slug}` = tenant slug'ınız (örn. `payven`). Onboarding sırasında size verilir.

```bash
curl https://identity.payven.com.tr/api/v1/auth/payven/token \
  -H "Content-Type: application/json" \
  -d '{
    "client_id":     "pvk-payven-live-a1b2c3d4",
    "client_secret": "YOUR_CLIENT_SECRET"
  }'
```

**Yanıt** (`200 OK`):

```json
{
  "token": {
    "access_token":        "eyJhbGciOiJSUzI1NiI...",
    "refresh_token":       "eyJhbGciOiJIUzI1NiI...",
    "expires_in":          300,
    "refresh_expires_in":  0,
    "token_type":          "Bearer",
    "scope":               "openid profile email"
  },
  "challenge": null
}
```

Yanıt `{ token, challenge }` zarfındadır. `client_credentials` akışında `challenge` **her zaman
`null`** gelir — bu alan yalnızca kullanıcı login'inde (OTP zorunlu tenant'larda) dolar.
Token alanlarını `token` nesnesinin içinden okuyun.

| Alan | Anlam |
|---|---|
| `token.access_token` | API çağrılarında kullanacağınız Bearer token (imzalı JWT formatında) |
| `token.refresh_token` | Access token expire olunca yenisini almak için |
| `token.expires_in` | Access token kaç saniye geçerli (varsayılan **300s = 5 dakika**) |
| `token.refresh_expires_in` | Refresh token süresi (`0` = idle timeout uygulanır, bkz. tablo) |
| `token.token_type` | Daima `Bearer` |
| `token.scope` | Tahsis edilen scope'lar (kimlik bilgisi üst kümesi). Endpoint-bazlı yetki bu alan üzerinden değil, kullanıcı/anahtar rollerinizden çözümlenir |
| `challenge` | `client_credentials` akışında daima `null` (OTP yalnız kullanıcı login'inde) |

## 2. Adım — API'yi çağır

```bash
curl https://vpos.payven.com.tr/api/v1/payments \
  -H "Authorization: Bearer eyJhbGciOiJSUzI1NiI..." \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: order-1001-payment" \
  -d '{
    "external_id": "ORDER-1001",
    "amount":      { "amount": 15000, "currency": "TRY" },
    "installment": 1,
    "card": {
      "holder_name":  "Test Kullanici",
      "number":       "4546711234567894",
      "expire_month": "12",
      "expire_year":  "2030",
      "cvv":          "000"
    }
  }'
```

**Bayiye bağlı** anahtarla ek bir merchant header'ı göndermeniz gerekmez; bayi token'dan çözümlenir (token'daki bayiyle çelişen header `403 merchant_context_mismatch` alır). **Organizasyon geneli** anahtarla işlem yapan uçlarda `X-Merchant-Id` (UUID) ya da `X-External-Merchant-Id` header'ı zorunludur; yoksa `400 merchant_context_missing` döner — bkz. [Hesap Yapısı](/documentation/account-model#merchant-kimligi-iki-form) ve [Sanal POS → Kimlik Doğrulama](/sanal-pos/authentication).

## 3. Adım — Token yenile

Access token expire olduğunda (`expires_in` süresi geçince) yenisini almak için `refresh_token` ile:

```bash
curl https://identity.payven.com.tr/api/v1/auth/payven/refresh \
  -H "Content-Type: application/json" \
  -d '{
    "refresh_token": "eyJhbGciOiJIUzI1NiI..."
  }'
```

Yanıt yine `access_token` + (rotasyonlu) `refresh_token` döner. Eski `refresh_token` artık geçersizdir —
**yanıttaki yeni `refresh_token`'ı saklayın**.

`401` dönerse gövdedeki `code` ne yapmanız gerektiğini söyler:

| `code` | Anlamı | Doğru davranış |
|---|---|---|
| `refresh_token_expired` | Oturum sona erdi (2 saat boşta ya da 10 saat mutlak sınır) — **beklenen** | `client_credentials` ile yeniden token alın. Alarm üretmeyin. |
| `refresh_token_invalid` | Token bozuk, başka realm'e ait veya iptal edilmiş | Saklama/kod hatası — inceleyin |
| `client_unauthorized` | API anahtarı pasif, silinmiş veya secret değişmiş | Retry etmeyin; anahtar durumunu kontrol edin |

<Note>
`/refresh` yanıtı **zarfsız** (düz) token nesnesidir: `{ access_token, refresh_token, expires_in, ... }`.
Zarf (`{ token, challenge }`) yalnızca `/token` (ve login) endpoint'lerinde kullanılır.
</Note>

## Token süreleri

| Token | Süre | Anlam |
|---|---|---|
| **Access token** | 5 dakika (300s) | API isteklerinde kullanılır. Süre dolunca refresh ile ya da yeniden `client_credentials` ile alınır. |
| **Refresh token** (varsayılan) | **2 saat boşta**, **10 saat mutlak** | Her refresh'te rotate edilir ve boşta süresi sıfırlanır — ancak oturumun 10 saatlik mutlak ömrü **uzatılamaz**. |
| **Refresh token** (offline — opsiyonel) | **30 gün boşta**, mutlak sınır yok | Yalnızca "offline refresh" izni verilmiş API anahtarlarında; `/token` isteğine `"offline": true` eklenerek alınır. |

<Warning>
**Refresh token sonsuza kadar yenilenmez.** Düzenli refresh yapsanız bile oturum 10 saatte
sona erer ve `/refresh` `401` döner. Bu bir hata değil, tasarımdır — entegrasyonunuz bu durumda
`client_credentials` ile **yeniden token almalıdır**. Aşağıdaki kod örnekleri bunu otomatik yapar
(refresh başarısız olursa key + secret ile baştan token alır).
</Warning>

<Note>
**Sunucu-sunucu entegrasyonda refresh kullanmak zorunda değilsiniz.** Key + secret elinizde
olduğu sürece süresi dolan token için `/token`'ı yeniden çağırmak tek istektir ve oturum
süreleri sizi hiç ilgilendirmez. Refresh yolu, token'ı yeniden alamayan istemciler
(tarayıcı/mobil oturumları) içindir.
</Note>

<Note>
**Pratik öneri:** Access token'ı **expiry'sine 60 saniye kala** yenileyin (clock-skew + network latency için margin). Aşağıdaki kod örnekleri bunu otomatik yapar.

Oturumun son dakikalarında `expires_in` 300'den **küçük** dönebilir: hiçbir token oturumdan
uzun yaşayamaz, bu yüzden süre kalan oturum ömrüne kırpılır. `expires_in` değerini sabit
varsaymayın, yanıttan okuyun.
</Note>

<Warning>
**Token cache'leyin** — her API çağrısında yeniden token almayın. Identity üzerinde
rate limit vardır (token endpoint'i IP başına dakikada 60, `/refresh` dakikada 300).
Token'ı bellekte tutup expire olana kadar yeniden kullanın.
</Warning>

## Kod örnekleri (auto-refresh)

<CodeGroup>
```javascript Node.js
class PayvenClient {
  constructor({ slug, clientId, clientSecret, identityBaseUrl }) {
    this.slug = slug;
    this.clientId = clientId;
    this.clientSecret = clientSecret;
    this.identityBaseUrl = identityBaseUrl;
    this.accessToken = null;
    this.refreshToken = null;
    this.expiresAt = 0;
  }

  async getToken() {
    if (this.accessToken && Date.now() < this.expiresAt - 60_000) {
      return this.accessToken;
    }

    if (this.refreshToken && (await this.tryRefresh())) {
      return this.accessToken;
    }

    const res = await fetch(`${this.identityBaseUrl}/api/v1/auth/${this.slug}/token`, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        client_id: this.clientId,
        client_secret: this.clientSecret,
      }),
    });
    if (!res.ok) throw new Error(`Token alınamadı: ${res.status}`);
    const data = await res.json();
    // /token yanıtı { token, challenge } zarfındadır
    this.accessToken = data.token.access_token;
    this.refreshToken = data.token.refresh_token;
    this.expiresAt = Date.now() + data.token.expires_in * 1000;
    return this.accessToken;
  }

  async tryRefresh() {
    const res = await fetch(`${this.identityBaseUrl}/api/v1/auth/${this.slug}/refresh`, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ refresh_token: this.refreshToken }),
    });
    if (!res.ok) {
      this.refreshToken = null;
      return false;
    }
    const data = await res.json();
    this.accessToken = data.access_token;
    this.refreshToken = data.refresh_token;
    this.expiresAt = Date.now() + data.expires_in * 1000;
    return true;
  }

  async call(productBaseUrl, path, init = {}) {
    const token = await this.getToken();
    return fetch(productBaseUrl + path, {
      ...init,
      headers: {
        ...(init.headers ?? {}),
        Authorization: `Bearer ${token}`,
      },
    });
  }
}
```

```python Python
import time
import httpx


class PayvenClient:
    def __init__(self, slug: str, client_id: str, client_secret: str, identity_base_url: str):
        self.slug = slug
        self.client_id = client_id
        self.client_secret = client_secret
        self.identity_base_url = identity_base_url
        self.access_token: str | None = None
        self.refresh_token: str | None = None
        self.expires_at: float = 0
        self._http = httpx.Client()

    def get_token(self) -> str:
        if self.access_token and time.time() < self.expires_at - 60:
            return self.access_token
        if self.refresh_token and self._refresh():
            return self.access_token  # type: ignore[return-value]

        r = self._http.post(
            f"{self.identity_base_url}/api/v1/auth/{self.slug}/token",
            json={"client_id": self.client_id, "client_secret": self.client_secret},
        )
        r.raise_for_status()
        data = r.json()["token"]  # /token yanıtı {token, challenge} zarfında
        self.access_token = data["access_token"]
        self.refresh_token = data["refresh_token"]
        self.expires_at = time.time() + data["expires_in"]
        return self.access_token

    def _refresh(self) -> bool:
        r = self._http.post(
            f"{self.identity_base_url}/api/v1/auth/{self.slug}/refresh",
            json={"refresh_token": self.refresh_token},
        )
        if r.status_code != 200:
            self.refresh_token = None
            return False
        data = r.json()
        self.access_token = data["access_token"]
        self.refresh_token = data["refresh_token"]
        self.expires_at = time.time() + data["expires_in"]
        return True
```

```csharp C#
public class PayvenClient
{
    private readonly HttpClient _http = new();
    private readonly string _slug, _clientId, _clientSecret, _identityBase;
    private string? _accessToken, _refreshToken;
    private DateTimeOffset _expiresAt;
    private readonly SemaphoreSlim _lock = new(1, 1);

    public PayvenClient(string slug, string clientId, string clientSecret, string identityBaseUrl)
        => (_slug, _clientId, _clientSecret, _identityBase) = (slug, clientId, clientSecret, identityBaseUrl);

    public async Task<string> GetTokenAsync(CancellationToken ct = default)
    {
        await _lock.WaitAsync(ct);
        try
        {
            if (_accessToken is not null && DateTimeOffset.UtcNow < _expiresAt.AddSeconds(-60))
                return _accessToken;

            if (_refreshToken is not null && await TryRefreshAsync(ct))
                return _accessToken!;

            var resp = await _http.PostAsJsonAsync(
                $"{_identityBase}/api/v1/auth/{_slug}/token",
                new { client_id = _clientId, client_secret = _clientSecret }, ct);
            resp.EnsureSuccessStatusCode();
            // /token yanıtı { token, challenge } zarfında
            var envelope = await resp.Content.ReadFromJsonAsync<TokenEnvelope>(cancellationToken: ct);
            var data = envelope!.token;
            _accessToken = data.access_token;
            _refreshToken = data.refresh_token;
            _expiresAt = DateTimeOffset.UtcNow.AddSeconds(data.expires_in);
            return _accessToken;
        }
        finally { _lock.Release(); }
    }

    private async Task<bool> TryRefreshAsync(CancellationToken ct)
    {
        var resp = await _http.PostAsJsonAsync(
            $"{_identityBase}/api/v1/auth/{_slug}/refresh",
            new { refresh_token = _refreshToken }, ct);
        if (!resp.IsSuccessStatusCode) { _refreshToken = null; return false; }
        var data = await resp.Content.ReadFromJsonAsync<TokenResponse>(cancellationToken: ct);
        _accessToken = data!.access_token;
        _refreshToken = data.refresh_token;
        _expiresAt = DateTimeOffset.UtcNow.AddSeconds(data.expires_in);
        return true;
    }

    private record TokenEnvelope(TokenResponse token);
    private record TokenResponse(string access_token, string refresh_token, int expires_in);
}
```

```go Go
package payven

import (
    "bytes"
    "encoding/json"
    "fmt"
    "net/http"
    "sync"
    "time"
)

type Client struct {
    Slug, ClientID, ClientSecret, IdentityBase string
    accessToken, refreshToken                  string
    expiresAt                                  time.Time
    mu                                         sync.Mutex
}

type tokenResponse struct {
    AccessToken  string `json:"access_token"`
    RefreshToken string `json:"refresh_token"`
    ExpiresIn    int    `json:"expires_in"`
}

// /token yanıtı { token, challenge } zarfında; /refresh düz tokenResponse döner.
type tokenEnvelope struct {
    Token tokenResponse `json:"token"`
}

func (c *Client) GetToken() (string, error) {
    c.mu.Lock()
    defer c.mu.Unlock()

    if c.accessToken != "" && time.Now().Before(c.expiresAt.Add(-60*time.Second)) {
        return c.accessToken, nil
    }
    if c.refreshToken != "" {
        if err := c.refresh(); err == nil {
            return c.accessToken, nil
        }
    }
    body, _ := json.Marshal(map[string]string{
        "client_id":     c.ClientID,
        "client_secret": c.ClientSecret,
    })
    return c.fetchToken(fmt.Sprintf("%s/api/v1/auth/%s/token", c.IdentityBase, c.Slug), body)
}
```

```php PHP
<?php
class PayvenClient {
    private string $slug, $clientId, $clientSecret, $identityBase;
    private ?string $accessToken = null, $refreshToken = null;
    private int $expiresAt = 0;

    public function __construct(string $slug, string $clientId, string $clientSecret, string $identityBase) {
        $this->slug = $slug; $this->clientId = $clientId;
        $this->clientSecret = $clientSecret; $this->identityBase = $identityBase;
    }

    public function getToken(): string {
        if ($this->accessToken && time() < $this->expiresAt - 60) return $this->accessToken;
        if ($this->refreshToken && $this->refresh()) return $this->accessToken;

        $resp = $this->post("/api/v1/auth/{$this->slug}/token", [
            "client_id"     => $this->clientId,
            "client_secret" => $this->clientSecret,
        ]);
        $token = $resp["token"]; // /token yanıtı {token, challenge} zarfında
        $this->accessToken = $token["access_token"];
        $this->refreshToken = $token["refresh_token"];
        $this->expiresAt = time() + $token["expires_in"];
        return $this->accessToken;
    }

    private function post(string $path, array $body): array {
        $ch = curl_init($this->identityBase . $path);
        curl_setopt_array($ch, [
            CURLOPT_RETURNTRANSFER => true,
            CURLOPT_POST => true,
            CURLOPT_HTTPHEADER => ["Content-Type: application/json"],
            CURLOPT_POSTFIELDS => json_encode($body),
        ]);
        $body = curl_exec($ch);
        $code = curl_getinfo($ch, CURLINFO_HTTP_CODE);
        curl_close($ch);
        if ($code !== 200) throw new Exception("Token request failed: $code");
        return json_decode($body, true);
    }
}
```

## Hata response'ları

### Token uçları (`/token`, `/refresh`)

| HTTP | `code` | Anlam | Çözüm |
|---|---|---|---|
| `400` | `client_credentials_required` | `client_id` ya da `client_secret` boş | İki alanı da dolu gönderin |
| `401` | `client_unauthorized` | Anahtar ya da secret geçersiz; anahtar pasif ya da silinmiş | Retry etmeyin; anahtar durumunu ve secret'ı kontrol edin |
| `401` | `api_key_expired` | Anahtarın son kullanma tarihi geçmiş | Yeni anahtar oluşturun ya da süresini uzatın |
| `403` | `api_key_ip_not_allowed` | İstek, anahtarın izinli IP listesinde olmayan bir adresten geldi | [IP Whitelist](/documentation/concepts/ip-whitelist) |
| `401` | `refresh_token_expired` | `/refresh`: oturum sona erdi (**beklenen**) | `client_credentials` ile yeniden token alın |
| `401` | `refresh_token_invalid` | `/refresh`: token bozuk, başka realm'e ait ya da iptal edilmiş | Saklama/kod hatası, inceleyin |
| `404` | `tenant_not_found` | `{slug}` geçersiz | Onboarding'de verilen kısa adı kontrol edin |
| `429` | `rate_limit_exceeded` | Token endpoint'ine çok istek | `Retry-After` header'ına uyun, token'ı cache'leyin |

### Ürün API'leri

| HTTP | `code` | Anlam |
|---|---|---|
| `401` | `unauthorized` | Token yok, geçersiz ya da süresi dolmuş: yeni token alın |
| `401` | `audience_invalid` | Token bu ürün için geçerli değil: anahtarın ürün seçimine bu ürünü ekleyin |
| `401` | `api_key_expired` | Anahtarın süresi dolmuş |
| `403` | `api_key_ip_not_allowed` | İstek izinli IP dışından geldi |
| `403` | `credential_read_only` | `read_only` anahtar durum değiştiren (POST/PUT/PATCH/DELETE) bir uca istek attı |
| `403` | `forbidden` | Anahtarın/rolün bu işlem için izni yok |
| `403` | `feature_not_available` | Ürün organizasyonunuzda ya da bayinin paketinde etkin değil |
| `403` | `merchant_context_mismatch` | Header'daki bayi, token'daki bayiyle uyuşmuyor |
| `400` | `merchant_context_missing` | Organizasyon geneli anahtarla bayi header'ı gönderilmedi |

Tam yanıt formatı için: [Hata Yönetimi](/documentation/concepts/errors).

## Güvenlik kuralları

<Check>**`client_secret` server-side saklanır** — frontend kodunuza, mobil uygulamanıza, public repo'ya **asla** koymayın.</Check>
<Check>**Token cache bellek-içi** — diske yazmayın; restart sonrası yeniden token alın.</Check>
<Check>**HTTPS zorunlu** — HTTP istekleri reddedilir.</Check>
<Check>**Token rotasyonu** — refresh otomatik yapar; manuel rotation gerekmez. Şüpheli durumda Identity'den client'ın secret'ını rotate edin.</Check>
<Check>**Loglarda maskele** — `access_token`, `refresh_token`, `client_secret` değerlerini log'lara yazmayın.</Check>

## SSS

<AccordionGroup>
  <Accordion title="Tek bir secret ile doğrudan API çağıramaz mıyım?">
    Hayır — Payven iki adımlı bir akış kullanır: önce `client_id` + `client_secret` ile kısa ömürlü bir access token alırsınız, sonra her API çağrısında bu token'ı kullanırsınız. Üstteki kod örneklerindeki istemci sınıfı bu adımı sizin için saklar; tek bir `call(...)` ile çağırırsınız.
  </Accordion>
  <Accordion title="Token süresini uzatabilir miyim?">
    Access token süresi 5 dakikadır ve değişmez; sunucu-sunucu entegrasyonda yeniden `/token` çağırmak tek istektir. Refresh token ömrü yukarıdaki tabloda. Arka planda kesintisiz çalışan entegrasyonlar için anahtar oluşturulurken **offline erişim** izni açılabilir; bu anahtarlar `/token` isteğine `"offline": true` ekleyerek günlerce yaşayan bir refresh token alır. Offline refresh token uzun ömürlü bir kimliktir; yalnız gerçekten gerekliyse açın.
  </Accordion>
  <Accordion title="Birden fazla servisi tek token'la çağırabilir miyim?">
    Evet — token, anahtarın oluşturulurken seçilen ürünlerin hepsinde geçerlidir. Sanal POS, Para Transferi, Cüzdan, Identity gibi ürünler aynı token ile çağrılır. Seçilmeyen bir ürün `401 audience_invalid` döner.
  </Accordion>
  <Accordion title="Test (sandbox) ortamı?">
    Test için ayrı adres yoktur. Aynı adreste **test ortamlı bir API anahtarı** (`client_id` içinde `-test-`) kullanırsınız; bu anahtarla yapılan her istek test modunda işlenir, bankaya gitmez ve gerçek para hareketi oluşturmaz. Canlı için ayrı bir anahtar üretilir. Bkz. [Hızlı Başlangıç](/documentation/quickstart).
  </Accordion>
</AccordionGroup>
