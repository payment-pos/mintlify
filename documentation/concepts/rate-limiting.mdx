Payven, suistimali engellemek ve adil kaynak paylaşımı sağlamak için tüm API'lerde istek limiti uygular. Limit **dakikalık sabit pencereyle** sayılır ve şu anahtar için ayrı ayrı tutulur:

**organizasyon + istemci + uç yolu**

- **İstemci**, API anahtarı ile gelen çağrılarda anahtarın kendisi, kullanıcı oturumunda kullanıcı, kimliksiz çağrılarda istemci IP'sidir. Aynı organizasyondaki iki anahtar birbirinin kotasını tüketmez.
- **Uç yolu**, istek yoludur (kimlik/GUID kısımları aynı kabul edilir): `/payments` ve `/checkout/sessions` ayrı sayaçlardır.

## Limitler

Her uç bir **dakikalık** limite sahiptir. Varsayılan değerler:

| Kapsam | Varsayılan (istek / dk) |
|---|---|
| Tüm uçlar (genel varsayılan) | 1.000 |
| Sanal POS: `payments` (ödeme, iade, iptal, kapama, 3D init) | 100 |
| Sanal POS: `checkout` (Hosted Checkout oturumu ve sayfası) | 200 |
| Sanal POS: `3d/callback` (banka dönüşü) | 20 |
| Cüzdan: `balance-topups` | 100 |
| e-Fatura: `invoices`, `taxpayers` | 300 |

Bir uç yolu birden fazla kalıba uyuyorsa ilk eşleşen limit uygulanır. Değerler **organizasyon bazında** Identity ayarlarından (`ratelimit:config`) değiştirilebilir; değişiklik yeniden dağıtım gerektirmez. Anahtarınıza bağlı bir plan kotası varsa limit, anahtarın saniyelik kotasının dakikaya çevrilmiş hali ile uç limitinin **küçüğüdür**.

Kendi limitlerinizi görmek için herhangi bir yanıttaki `X-RateLimit-*` başlıklarına bakın. Yüksek hacim ihtiyacınız için [destek ekibine](/resources/support) yazın.

### Kimlik uçları

Token alma ve oturum uçları ayrı, IP başına dakikalık limit taşır:

| Uç | Limit |
|---|---|
| `POST /auth/{slug}/token` (client credentials) | 60 / dk / IP |
| `POST /auth/{slug}/refresh` | 300 / dk / IP |
| `POST /auth/{slug}/login` ve ilgili oturum uçları | 60 / dk / IP |

Access token 5 dakika yaşadığı için düzgün cache'leyen bir istemci yaklaşık 5 dakikada bir istek yapar; bu limit yalnız kaçak döngüleri durdurur. **Her API çağrısında yeni token almayın.**

<Note>
**Webhook teslimleri limitten muaftır.** Payven'in size gönderdiği webhook çağrıları bu limitlere sayılmaz; ayrı bir teslim ve yeniden deneme mekanizmasına tabidir.
</Note>

## Yanıt başlıkları

Her API yanıtı, ilgili uç için kotanızı bildiren başlıklar döner:

```http
X-RateLimit-Limit:      100
X-RateLimit-Remaining:  87
X-RateLimit-Reset:      1790000060
```

| Başlık | Açıklama |
|---|---|
| `X-RateLimit-Limit` | Bu uç için **dakikadaki** maksimum istek sayısı |
| `X-RateLimit-Remaining` | Bu pencerede kalan istek hakkı |
| `X-RateLimit-Reset` | Pencerenin biteceği an (Unix saniye) |

## Idempotent tekrar denemeler

`Idempotency-Key` ile gelen ve daha önce tamamlanmış bir isteğin tekrarı (yanıt `Idempotent-Replayed: true`) limit sayacına **girmeden** önceki yanıtı döner. Bu yüzden zaman aşımı sonrası aynı anahtarla yapılan tekrar denemeler kotanızı tüketmez. Bkz. [Idempotency](/documentation/concepts/idempotency).

## Limit aşımı

Kota aşıldığında `429 Too Many Requests` döner. Yanıt problem+json zarfındadır ve `Retry-After` header'ı kaç saniye bekleyeceğinizi belirtir (API uçlarında 60 saniye):

```http
HTTP/1.1 429 Too Many Requests
Content-Type: application/problem+json
Retry-After: 60
```

```json
{
  "type":     "https://docs.payven.com.tr/errors/rate_limit_exceeded",
  "title":    "Rate limit exceeded",
  "status":   429,
  "code":     "rate_limit_exceeded",
  "detail":   "Çok fazla istek gönderildi; 60 saniye sonra tekrar deneyin.",
  "message":  "Çok fazla istek gönderildi; 60 saniye sonra tekrar deneyin.",
  "category": "rate_limit_error",
  "correlation_id": "9f1c8e76-2a3b-4f12-9c8d-12cb24a8a8a8"
}
```

## Önerilen istemci davranışı

<CodeGroup>
```csharp C#
async Task<HttpResponseMessage> SendWithBackoff(Func<HttpRequestMessage> makeRequest)
{
    while (true)
    {
        var response = await http.SendAsync(makeRequest());
        if (response.StatusCode != (HttpStatusCode)429) return response;

        var retryAfter = response.Headers.RetryAfter?.Delta
                         ?? TimeSpan.FromSeconds(5);
        await Task.Delay(retryAfter);
    }
}
```

```javascript Node.js
async function sendWithBackoff(url, options) {
  while (true) {
    const res = await fetch(url, options);
    if (res.status !== 429) return res;
    const retry = parseInt(res.headers.get("Retry-After") ?? "5", 10);
    await new Promise((r) => setTimeout(r, retry * 1000));
  }
}
```
</CodeGroup>

Limite yaklaşan toplu işlerde `X-RateLimit-Remaining` değerini izleyip istek hızını önceden düşürmek, 429 ile karşılaşmaktan iyidir. Ödeme gibi para hareketi yapan isteklerde yeniden denemeyi mutlaka **aynı `Idempotency-Key`** ile yapın.
