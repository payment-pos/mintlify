Payven hata yanıtları [RFC 9457 — Problem Details for HTTP APIs](https://www.rfc-editor.org/rfc/rfc9457) standardına uyar. Tüm hata gövdeleri `application/problem+json` tipindedir ve **tek zarfı** kullanır. HTTP durum kodu hatanın sınıfını, gövdedeki `code` alanı programatik tipini belirtir.

## Hata yanıt formatı

```http
HTTP/1.1 422 Unprocessable Entity
Content-Type: application/problem+json
X-Correlation-Id: 9f1c8e76-2a3b-4f12-9c8d-12cb24a8a8a8
```

```json
{
  "type":           "https://docs.payven.com.tr/errors/REFUND_AMOUNT_EXCEEDS_REMAINING",
  "title":          "İade tutarı kalan tutarı aşıyor",
  "status":         422,
  "code":           "REFUND_AMOUNT_EXCEEDS_REMAINING",
  "detail":         "İade tutarı kalan tutarı (15000 kuruş) aşamaz.",
  "message":        "İade tutarı kalan tutarı (15000 kuruş) aşamaz.",
  "category":       "invalid_request_error",
  "instance":       "/api/v1/payments/8e3f5c12-.../refund",
  "correlation_id": "9f1c8e76-2a3b-4f12-9c8d-12cb24a8a8a8"
}
```

| Alan | Açıklama |
|---|---|
| `type` | Hata tipinin URI'si (`.../errors/{code}`). |
| `title` | Kısa başlık. |
| `status` | HTTP durum kodu (header ile aynı). |
| `code` | **Programatik hata kodu.** Karar için bunu kullanın; kodu birebir string olarak karşılaştırın. |
| `detail` / `message` | İnsan-okur açıklama. `message`, `detail`'in aynasıdır. Metin dile göre değişebilir, ona göre karar vermeyin. |
| `category` | Hatanın sınıfı: `invalid_request_error`, `authentication_error`, `permission_error`, `rate_limit_error`, `idempotency_error`, `provider_error`, `api_error`. Genel bir hata işleyici için `code` yerine `category` yeterlidir. |
| `param` | Doğrulama hatasında ilk hatalı alan (örn. `request_card_holder_name`). |
| `provider_error_code` | Yalnız banka/sağlayıcı reddinde: bankanın **ham** kodu (örn. `"51"`). |
| `errors[]` | Yalnız `validation_failed`'da: alan bazlı hata listesi (aşağıda). |
| `instance` | İsteğin yolu. |
| `correlation_id` | İstek zinciri kimliği; `X-Correlation-Id` header'ı ile aynı. Destek talebinde paylaşın. |

## HTTP kategorileri

| HTTP | Anlam | Örnek `code` | Retry |
|---|---|---|---|
| `400` | Geçersiz gövde, eksik bağlam | `bad_request`, `merchant_context_missing` | Düzeltmeden tekrarlamayın |
| `401` | Token yok, geçersiz, süresi dolmuş | `unauthorized`, `client_unauthorized`, `audience_invalid` | Yeniden token alın |
| `403` | Yetki yok, modül kapalı, IP izinli değil | `forbidden`, `feature_not_available`, `api_key_ip_not_allowed`, `credential_read_only` | Hayır |
| `404` | Kaynak bulunamadı | `resource_not_found` | Hayır |
| `409` | Çakışma, geçersiz durum geçişi, idempotency | `conflict`, `invalid_state`, `idempotency_key_in_use`, `idempotency_request_in_progress` | Hayır (in-progress hariç) |
| `422` | İş kuralı ya da doğrulama ihlali | `validation_failed`, `PV_BANK_DECLINED`, `merchant_inactive` | Hayır, isteği düzeltin |
| `429` | Rate limit aşıldı (`Retry-After`) | `rate_limit_exceeded` | Backoff |
| `500/502/503/504` | Sunucu / bağlantı / zaman aşımı | `internal_server_error`, `service_unavailable`, `PV_TIMEOUT` | Backoff, aynı `Idempotency-Key` ile |

<Note>
**Banka reddi de bir hata yanıtıdır.** Bankaya ulaşmış ama reddedilen ödeme `422` + `application/problem+json` döner; gövdede `code: "PV_BANK_DECLINED"` (ya da daha spesifik bir `PV_` kodu) ve bankanın ham kodu `provider_error_code` alanında yer alır. Sonucu HTTP durum koduyla değerlendirin; `200` gövdesinde ret aramayın.
</Note>

## Kod kümeleri

`code` alanı üç kaynaktan gelir. **Kodu birebir (büyük/küçük harf duyarlı) karşılaştırın**; bir kümenin kodunu diğerinin biçimiyle aramayın.

| Küme | Biçim | Kim üretir | Liste |
|---|---|---|---|
| **Altyapı kodları** | `lowercase_snake_case` | Ortak API katmanı: kimlik, doğrulama, rate limit, idempotency, bayi bağlamı | Aşağıdaki tablolar |
| **Ürün / iş kuralı kodları** | Çoğu `PV_BÜYÜK_HARF` (bazıları `BÜYÜK_HARF`) | İlgili ürün (Sanal POS, Para Transferi...) | [Sanal POS → Payven Domain Kodları](/sanal-pos/errors/payven-codes) |
| **Banka kodları** | Bankaya göre | Banka; `provider_error_code` alanında döner, `code`'da **değil** | [Banka Yanıt Kodları](/sanal-pos/errors/bank-codes) |

## Yaygın altyapı kodları

### Kimlik doğrulama ve yetki

| `code` | HTTP | Anlam |
|---|---|---|
| `unauthorized` | 401 | Token yok, geçersiz, süresi dolmuş ya da imza doğrulanamadı |
| `client_unauthorized` | 401 | `/token` veya `/refresh`: API anahtarı geçersiz, pasif ya da silinmiş. **Retry etmeyin** |
| `refresh_token_expired` | 401 | `/refresh`: oturum sona erdi. **Beklenen**: `client_credentials` ile yeniden token alın |
| `refresh_token_invalid` | 401 | `/refresh`: token bozuk, başka realm'e ait ya da iptal edilmiş |
| `api_key_expired` | 401 | Anahtarın son kullanma tarihi geçmiş |
| `audience_invalid` | 401 | Token bu ürün için geçerli değil (anahtarın ürün seçiminde yok) |
| `forbidden` | 403 | Rol/anahtar bu kaynağa erişemez |
| `api_key_ip_not_allowed` | 403 | İstek anahtarın izinli IP listesi dışından geldi |
| `credential_read_only` | 403 | `read_only` anahtar durum değiştiren bir istek attı |
| `feature_not_available` | 403 | Modül organizasyonda ya da bayinin paketinde etkin değil |

### Bayi bağlamı

| `code` | HTTP | Anlam |
|---|---|---|
| `merchant_context_missing` | 400 | Hiçbir bayi formu (`X-Merchant-Id` / `X-External-Merchant-Id`) gelmedi |
| `merchant_context_mismatch` | 403 | Header'daki bayi token'daki bayiyle uyuşmuyor |
| `merchant_not_found` | 422 | Bayi bildirildi ama kayda çözülemedi |
| `merchant_inactive` | 422 | Bayi pasif: giriş yapar ama işlem yapamaz |
| `merchant_not_approved` | 422 | Bayi onaysız: işlem yapamaz |
| `merchant_limit_exceeded` | 422 | İşlem bayinin tanımlı limitini aşıyor |

400 "hangi bayi olduğunu söylemediniz", 422 "söylediniz ama bu bayi kullanılamaz" demektir. Bu yüzden "bayi bulunamadı" 404 değildir.

<Note>
`PV_MERCHANT_INACTIVE` (bankadaki üye işyeri/terminal pasif) ile `merchant_inactive` (Payven'deki bayi kaydı pasif) farklı şeylerdir.
</Note>

### İstek formatı ve doğrulama

| `code` | HTTP | Anlam |
|---|---|---|
| `bad_request` | 400 | Genel istek hatası: gövde okunamadı, alan tipi hatalı |
| `validation_failed` | 422 | Doğrulama kuralı ihlali: `errors[]` ile alan listesi |
| `unsupported_media_type` | 415 | `Content-Type` `application/json` değil |
| `method_not_allowed` | 405 | HTTP metodu bu yol için tanımlı değil |
| `not_acceptable` | 406 | `Accept` header'ı desteklenmiyor |
| `external_id_required` | 422 | `POST /payments` gibi uçlarda `external_id` zorunlu |

<Warning>
İstek gövdesindeki alan adları **snake_case** ve büyük/küçük harf **duyarlıdır** (`holder_name`, `HolderName` değil). Query parametreleri de snake_case olmalıdır (`page_size`); `pageSize` gönderirseniz `400` alırsınız.
</Warning>

Doğrulama hatalarında alan bazlı detay `errors[]` dizisinde döner. Alan adları snake_case'dir ve iç içe alanların `.` ayırıcısı `_` olur:

```json
{
  "type":     "https://docs.payven.com.tr/errors/validation_failed",
  "title":    "Validation failed",
  "status":   422,
  "code":     "validation_failed",
  "detail":   "One or more fields are invalid",
  "message":  "One or more fields are invalid",
  "category": "invalid_request_error",
  "param":    "request_card_holder_name",
  "errors": [
    {
      "field":   "request_card_holder_name",
      "code":    "not_empty_validator",
      "message": "Card holder name zorunludur."
    }
  ],
  "correlation_id": "9f1c8e76-2a3b-4f12-9c8d-12cb24a8a8a8"
}
```

Alan hata kodları (`not_empty_validator`, `greater_than_validator` ...) doğrulama kuralının adıdır; kullanıcıya göstermek için `field` ve `message` alanlarını kullanın.

### Kaynak ve durum

| `code` | HTTP | Anlam |
|---|---|---|
| `resource_not_found` | 404 | Kaynak bulunamadı (başka bayinin kaynağı da 404 döner) |
| `conflict` | 409 | Genel çakışma |
| `invalid_state` | 409 | Kaynak bu işlem için uygun durumda değil |

### Ödeme, iade, 3D Secure ve banka hataları

Bu hatalar **ürün kodu** olarak döner. Sık karşılaşılanlar:

| `code` | HTTP | Anlam |
|---|---|---|
| `PV_BANK_DECLINED` | 422 | Banka işlemi reddetti: ham kod `provider_error_code`'da |
| `PV_INSUFFICIENT_FUNDS` | 422 | Bakiye yetersiz |
| `PV_CARD_EXPIRED` | 422 | Kartın son kullanma tarihi geçmiş |
| `PV_DO_NOT_HONOR` | 422 | Banka işleme izin vermedi |
| `PV_3DS_FAILED` | 422 | 3D Secure doğrulaması başarısız |
| `PV_FRAUD_SUSPECTED` | 422 | Banka işlemi güvenlik nedeniyle reddetti (örn. kayıp/çalıntı kart) |
| `fraud_declined` | 422 | Fraud kural motoru (Block kararı) işlemi engelledi: işlem oluşmaz, bankaya gidilmez. Bkz. [Fraud Yönetimi](/fraud/overview) |
| `PV_NON_3D_NOT_ALLOWED` | 422 | Non-3D ödeme bu bayi için kapalı |
| `PV_CANNOT_REFUND` | 409 | Mevcut durumda iade yapılamaz |
| `PV_TIMEOUT` | 504 | İşlem zaman aşımına uğradı: sonucu sorgulayın, körlemesine tekrar göndermeyin |

Tam liste: [Sanal POS → Payven Domain Kodları](/sanal-pos/errors/payven-codes). Banka ham kodları: [Banka Yanıt Kodları](/sanal-pos/errors/bank-codes).

### Idempotency ve rate limit

| `code` | HTTP | Anlam |
|---|---|---|
| `idempotency_key_in_use` | 409 | Aynı `Idempotency-Key` farklı gövdeyle kullanılmış |
| `idempotency_request_in_progress` | 409 | Aynı anahtarlı ilk istek hâlâ işleniyor: `Retry-After` kadar sonra aynı anahtarla tekrar deneyin |
| `rate_limit_exceeded` | 429 | İstek limiti aşıldı: `Retry-After` header'ına uyun |

## Retry stratejisi

Sadece **geçici hatalar** için retry uygun: `429`, `5xx`, network timeout. **Idempotent olmayan** işlemleri retry ederken mutlaka aynı `Idempotency-Key` kullanın — yoksa aynı işlem birden fazla yapılır.

`5xx`, `408` ve `429` yanıtları idempotency önbelleğine **yazılmaz**: aynı `Idempotency-Key` ile tekrar denediğinizde hata değil, işlemin gerçek sonucu alınır. `4xx` iş kuralı hataları ise önbelleğe yazılır ve aynı anahtarla aynı hata döner; düzeltilmiş istek için yeni anahtar kullanın.

Önerilen pattern: **exponential backoff + jitter**.

```
1. deneme: hemen
2. deneme: ~1 sn sonra
3. deneme: ~2 sn sonra
4. deneme: ~4 sn sonra
5. deneme: ~8 sn sonra (üst limit)
```

<CodeGroup>
```csharp C#
async Task<HttpResponseMessage> SendWithRetryAsync(
    Func<HttpRequestMessage> requestFactory,
    int maxAttempts = 5,
    CancellationToken ct = default)
{
    var rng = new Random();
    for (int attempt = 0; ; attempt++)
    {
        var response = await _http.SendAsync(requestFactory(), ct);
        if (response.IsSuccessStatusCode) return response;

        var status = (int)response.StatusCode;
        var retryable = status == 429 || status >= 500;
        if (!retryable || attempt >= maxAttempts - 1) return response;

        var delaySec = Math.Pow(2, attempt);
        if (response.Headers.RetryAfter?.Delta is { } ra) delaySec = ra.TotalSeconds;
        var jitter = rng.NextDouble() * 0.5;
        await Task.Delay(TimeSpan.FromSeconds(delaySec + jitter), ct);
    }
}
```

```javascript Node.js
async function retry(makeRequest, { maxAttempts = 5 } = {}) {
  for (let attempt = 0; ; attempt++) {
    const res = await makeRequest();
    if (res.ok) return res;

    const retryable = res.status === 429 || res.status >= 500;
    if (!retryable || attempt >= maxAttempts - 1) return res;

    const retryAfter = Number(res.headers.get("retry-after"));
    const baseSec = Number.isFinite(retryAfter) ? retryAfter : 2 ** attempt;
    const jitter = Math.random() * 0.5;
    await new Promise((r) => setTimeout(r, (baseSec + jitter) * 1000));
  }
}
```

```python Python
import asyncio, random

async def retry(make_request, max_attempts: int = 5):
    for attempt in range(max_attempts):
        res = await make_request()
        if 200 <= res.status_code < 300:
            return res

        retryable = res.status_code == 429 or res.status_code >= 500
        if not retryable or attempt == max_attempts - 1:
            return res

        retry_after = res.headers.get("retry-after")
        base = float(retry_after) if retry_after else 2 ** attempt
        await asyncio.sleep(base + random.random() * 0.5)
```
</CodeGroup>

<Tip>
Tekrar denerken **aynı `Idempotency-Key`** ile gönderin. Aynı işlemin iki kez
oluşmasını engeller. Bkz. [Idempotency](/documentation/concepts/idempotency).
</Tip>

## Müşteriye gösterme

`detail` alanı son kullanıcıya gösterilebilir nitelikte yazılır. Yine de hassas durumlarda (fraud, fraud-review, banka tarafı reddi) genel bir mesajla geçiştirmek daha güvenlidir:

```javascript
function userMessage(problem) {
  switch (problem.code) {
    case "validation_failed":
      return problem.detail;
    // Ürün kodları PV_ öneklidir — snake_case ile karşılaştırmayın.
    case "PV_BANK_DECLINED":
    case "PV_DO_NOT_HONOR":
    case "PV_INSUFFICIENT_FUNDS":
    case "PV_FRAUD_SUSPECTED":
    case "fraud_declined":
      return "İşleminiz onaylanmadı. Farklı bir kart deneyebilirsiniz.";
    case "rate_limit_exceeded":
      return "Şu an çok fazla istek alıyoruz. Lütfen kısa bir süre sonra tekrar deneyin.";
    default:
      return "İşleminiz gerçekleştirilemedi. Lütfen tekrar deneyin.";
  }
}
```

## Destek talebi açarken

Her hata yanıtında dönen **`correlation_id`** değerini paylaşın — log zincirini saniyeler içinde bulabiliriz. Response header'ındaki `X-Correlation-Id` ile gövdedeki `correlation_id` aynı değerdir.

```text
Konu:   Refund 422 — REFUND_AMOUNT_EXCEEDS_REMAINING
Detay:  correlation_id: 9f1c8e76-2a3b-4f12-9c8d-12cb24a8a8a8
        instance:      /api/v1/payments/8e3f5c12-.../refund
        zaman:         2026-05-05T14:23:11+03:00
```
