Payven API'lerine erişim **OAuth 2.0 Client Credentials** akışı ile sağlanır:
`client_id` + `client_secret` → access token. `client_secret`, organizasyonunuz adına işlem yapma yetkisidir; sızdığında saldırganın elinde sizin adınıza ödeme oluşturma kapısı olur.

Aşağıdaki kurallara uymak sızıntı riskini ve sızıntı sonrası etkiyi minimuma indirir. Auth akışının tamamı için: [Kimlik Doğrulama](/documentation/concepts/authentication).

## Kuralname

<Check>**Asla kaynak kodda tutmayın**: `client_secret`'ı `.env`, secret manager veya environment variable olarak yönetin.</Check>
<Check>**Asla istemcide tutmayın**: tarayıcı, mobil uygulama veya desktop client'a göndermeyin. Token alma sunucu tarafında yapılmalı; istemciye yalnızca kısa ömürlü access token gider.</Check>
<Check>**Asla loglara yazmayın**: log framework'ünüzde request/response loglama açıksa `Authorization` header'ı ile `client_secret`, `refresh_token` body alanlarını maskeleyin.</Check>
<Check>**Asla destek ekibine paylaşmayın**: Payven destek ekibi sizden `client_secret` istemez.</Check>
<Check>**Test ve canlı anahtarı ayırın**: anahtarın ortamı (`test` / `live`) oluşturulurken seçilir ve değişmez; farklı secret store'lar kullanın.</Check>
<Check>**İzinli IP listesi tanımlayın**: canlı anahtarlar için zorunlu kabul edin ([IP Whitelist](/documentation/concepts/ip-whitelist)).</Check>
<Check>**Yetkiyi daraltın**: anahtarı yalnız ihtiyaç duyduğu ürünlerle (`features`) oluşturun; yalnız okuma yapan servisler için `read_only` erişim düzeyi seçin (yazma isteği `403 credential_read_only` alır).</Check>
<Check>**Son kullanma tarihi verin**: geçici entegrasyonlar için `expires_at` tanımlayın; süresi dolan anahtar `401 api_key_expired` döner.</Check>
<Check>**Düzenli rotasyon**: en az 6 ayda bir, sızıntı şüphesinde anında.</Check>
<Check>**API kayıtlarını izleyin**: panelde API kayıtları ekranında beklenmeyen istek varsa hemen tepki verin.</Check>
<Check>**Token cache uygulayın**: her istek öncesi yeni token almayın; access token süresi dolmadan (60 sn margin) yenileyin.</Check>

## Saklama önerileri

| Ortam | Önerilen secret store |
|---|---|
| AWS | AWS Secrets Manager veya Parameter Store (SecureString) |
| Azure | Azure Key Vault |
| GCP | Secret Manager |
| Kubernetes | External Secrets Operator + cloud KMS |
| On-premise | HashiCorp Vault |
| Geliştirme | `.env` (commit edilmez) + `direnv` veya `dotenv` |

## Çoklu client stratejisi

Tek bir client'la çalışmak yerine **işlevlere göre ayrılmış** anahtarlar oluşturmanız önerilir:

| Anahtar | Kullanım |
|---|---|
| `payments-prod` | Yalnız ödeme alan serviste kullanılan canlı anahtar |
| `reporting-prod` | Yalnız raporlama job'larında kullanılan, `read_only`, daha dar IP listeli canlı anahtar |
| `dev-team-test` | Geliştirici ekibinin paylaştığı test anahtarı |

Bir secret sızdığında etki alanı sınırlı kalır, denetimde hangi servisin ne yaptığını ayırt etmek kolaylaşır.

## Rotasyon prosedürü

`POST /merchants/me/api-keys/{id}/rotate-secret` (organizasyon geneli anahtarlarda `/tenants/me/api-keys/{id}/rotate-secret`) mevcut anahtarın secret'ını **hemen** yeniler: eski secret ve anahtara bağlı tüm açık oturumlar (refresh token'lar) aynı anda geçersiz olur. Bu yüzden kesintisiz rotasyon için secret'ı yenilemek yerine **yeni bir anahtar** oluşturup geçiş yapın:

<Steps>
  <Step title="Yeni anahtar oluşturun">
    Aynı ortam (`live`), ürün seçimi ve IP listesiyle yeni bir anahtar üretin. Eski anahtarı **silmeyin**; iki anahtar birlikte geçerlidir.
  </Step>
  <Step title="Yeni secret'ı secret store'a yazın">
    Canlı anahtarın secret'ı yalnız oluşturulurken gösterilir; hemen kaydedin.
  </Step>
  <Step title="Servisinizi yeniden deploy edin">
    Servis yeni `client_id` / `client_secret` ile token almaya başlasın. Eski instance'lar eski anahtarla çalışmayı sürdürür.
  </Step>
  <Step title="API kayıtlarını izleyin">
    Eski anahtarla gelen istek kalmadığını panelde API kayıtlarından doğrulayın.
  </Step>
  <Step title="Eski anahtarı silin ya da pasife alın">
    Trafik kesildiğinde eski anahtarı silin (`DELETE`) ya da pasife alın.
  </Step>
</Steps>

Kesintiyi göze alabileceğiniz durumlarda (örn. test anahtarı) `rotate-secret` tek adımdır; yeni secret yanıtta yalnız bir kez döner.

## Sızıntı şüphesinde acil müdahale

`client_secret`'ınızın sızdığını düşündüğünüz an aşağıdaki adımları **paralel** uygulayın:

<Steps>
  <Step title="Anahtarı hemen devre dışı bırakın">
    Anahtarı panelden pasife alın ya da silin; `rotate-secret` ile secret'ı yenilemek de eski secret'ı ve açık oturumları anında geçersiz kılar.
  </Step>
  <Step title="Yeni anahtar üretip servisinizi geçirin">
    Yukarıdaki rotasyon adımlarını hızlandırılmış uygulayın.
  </Step>
  <Step title="API kayıtlarını inceleyin">
    Sızıntı penceresindeki tüm istekleri panelde API kayıtlarından çıkarın; para hareketi yapan işlemleri ayrıca kontrol edin.
  </Step>
  <Step title="Destek ekibine bildirin">
    [Destek talebi](/resources/support) açın; etki analizi için yardım alın.
  </Step>
</Steps>

## Loglama kuralı

Request/response loglaması yapan kütüphaneler için header maskeleme örneği:

<CodeGroup>
```csharp C#
public class SensitiveHeaderRedactor : DelegatingHandler
{
    private static readonly string[] SensitiveHeaders =
    {
        "Authorization"
    };

    protected override async Task<HttpResponseMessage> SendAsync(
        HttpRequestMessage request, CancellationToken ct)
    {
        var clone = new HttpRequestMessage(request.Method, request.RequestUri);
        foreach (var header in request.Headers)
        {
            var value = SensitiveHeaders.Contains(header.Key, StringComparer.OrdinalIgnoreCase)
                ? new[] { "***REDACTED***" }
                : header.Value.ToArray();
            clone.Headers.Add(header.Key, value);
        }
        // logger logs `clone`, sends `request`
        return await base.SendAsync(request, ct);
    }
}
```

```javascript Node.js
function redactSensitive(headers) {
  const sensitive = ["authorization"];
  const safe = {};
  for (const [k, v] of Object.entries(headers)) {
    safe[k] = sensitive.includes(k.toLowerCase()) ? "***REDACTED***" : v;
  }
  return safe;
}

// Token alma isteklerinde body'deki client_secret'ı da maskelemeyi unutmayın
function redactBody(body) {
  if (typeof body !== "object" || body === null) return body;
  const safe = { ...body };
  if (safe.client_secret) safe.client_secret = "***REDACTED***";
  if (safe.refresh_token) safe.refresh_token = "***REDACTED***";
  return safe;
}

logger.info("payven request", {
  url,
  headers: redactSensitive(headers),
  body: redactBody(body),
});
```
</CodeGroup>
