title: "Alıcılar (Recipients)"
description: "Kayıtlı alıcı hesapları — düzenli transfer ettiğiniz kişi ve kurumları bir kez kaydedin."
---

Alıcı (recipient), düzenli transfer ettiğiniz kişilerin / kurumların **kayıtlı hesap bilgisidir**: ad, banka ve IBAN (ya da hesap numarası / kart token'ı) tek kayıtta durur. Alıcı kaydı iki yerde kullanılır:

- **Tekrarlayan transferler** alıcıyı `recipient_id` ile referans verir; IBAN alıcı kaydından okunur ([Tekrarlayan Transferler](/para-transferi/transfers/recurring)).
- **Tekil transferlerde** `recipient.recipient_id` yalnız oluşan alıcı hesabı kaydı alıcıya bağlar; IBAN yine istekte verilir ([1. Adım — Oluştur](/para-transferi/transfers/bulk-create#alıcı-bilgisi)).

## Ne zaman kullanılır?

| Senaryo | Kayıtlı alıcı | Ad-hoc IBAN |
|---|---|---|
| Tekrarlayan maaş / kira / abonelik | Evet (zorunlu) | — |
| Maaş bordrosu, tedarikçi ödemesi (her ay aynı kişiler) | Önerilir | Mümkün |
| Tek seferlik müşteri iadesi | — | Evet |

## Endpoint'ler

```http
POST   /api/v1/recipients                        # Yeni alıcı
GET    /api/v1/recipients                        # Liste (sayfalı)
GET    /api/v1/recipients/by-bank/{bank_id}      # Banka bazlı liste
PUT    /api/v1/recipients/{id}                   # Güncelleme (tam değiştirme)
DELETE /api/v1/recipients/{id}                   # Silme
POST   /api/v1/recipients/{id}/blacklist         # IBAN'ı kara listeye ekle
GET    /api/v1/recipients/export                 # CSV (scope=page|all)
GET    /api/v1/recipients/export/schema          # Kolon şeması
```

**Yetki:** okuma `CanViewRecipients`; oluşturma, güncelleme, silme ve kara liste `CanManageRecipients`.

## Alıcı oluşturma

```bash
curl -X POST https://transfer.payven.com.tr/api/v1/recipients \
  -H "Authorization: Bearer $PAYVEN_TOKEN" \
  -H "X-Merchant-Id: $MERCHANT_ID" \
  -H "Idempotency-Key: recipient-ahmet-yilmaz-2026" \
  -H "Content-Type: application/json" \
  -d '{
    "bank_id":      "5e0b0f2a-0000-0000-0000-000000000001",
    "holder_name":  "Ahmet Yılmaz",
    "first_name":   "Ahmet",
    "last_name":    "Yılmaz",
    "iban":         "TR330006100519786457841326",
    "description":  "Mayıs maaş listesi — Yazılım Ekibi"
  }'
```

| Alan | Tip | Zorunluluk | Açıklama |
|---|---|---|---|
| `bank_id` | UUID | Zorunlu | Alıcının bankası; [banka kataloğundaki](/identity/lookups/banks) **aktif** bir banka (`GET /api/v1/lookups/banks`) |
| `holder_name` | string | Zorunlu | Hesap sahibi adı (en fazla 250 karakter) |
| `first_name`, `last_name` | string | Opsiyonel | En fazla 100 karakter |
| `iban` | string | Hesap tanımlayıcısı | IBAN (en fazla 50 karakter) |
| `account_number` | string | Hesap tanımlayıcısı | Hesap numarası (en fazla 50 karakter) |
| `masked_card_no`, `card_token` | string | Kartlı alıcı | Maskeli kart numarası (en fazla 50) ve kart token'ı (en fazla 250) |
| `description` | string | Opsiyonel | Etiket / açıklama (en fazla 500 karakter) |

Bayi kapsamı `X-Merchant-Id` başlığından gelir; gövdede bayi alanı yoktur.

## Yanıt

```http
HTTP/1.1 201 Created
Content-Type: application/json
```

```json
"abc12345-0000-0000-0000-000000000000"
```

Gövde yeni alıcının kimliğidir (UUID string). Bu `id`'yi tekrarlayan transferde `recipient_id` olarak kullanırsınız.

## Listeleme

```bash
curl "https://transfer.payven.com.tr/api/v1/recipients?page_size=50&search_term=Yılmaz" \
  -H "Authorization: Bearer $PAYVEN_TOKEN"
```

Standart sayfalı liste yapısı döner (`items[]`: `id`, `bank_id`, `bank_name`, `bank_code`, `first_name`, `last_name`, `holder_name`, `description`, `iban`, `account_number`, `masked_card_no`, `card_token`).

| Sorgu parametresi | Açıklama |
|---|---|
| `search_term` | Serbest arama (en fazla 100 karakter) |
| `bank_id` | Banka filtresi (`/recipients/by-bank/{bank_id}` ile aynı) |
| `holder_name`, `first_name`, `last_name`, `iban`, `account_number` | Alan bazlı filtre |
| `extra_properties_search_term` | Ek özellik değerlerinde arama |
| `include_inactive` | Pasif kayıtları da getirir |

## Güncelleme

`PUT /recipients/{id}` kaydı **tam olarak değiştirir**: gönderilmeyen alanlar boşalır. Kaydı önce okuyup değişen alanlarla birlikte tamamını gönderin.

```bash
curl -X PUT https://transfer.payven.com.tr/api/v1/recipients/abc12345-... \
  -H "Authorization: Bearer $PAYVEN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "bank_id":     "5e0b0f2a-0000-0000-0000-000000000001",
    "holder_name": "Ahmet Yılmaz",
    "iban":        "TR330006100519786457841326",
    "description": "Maaş — yeni şirket"
  }'
```

Yanıt `200`, gövde alıcı kimliğidir.

## Silme

`DELETE /recipients/{id}` `204` döner. Kayıt silinir (soft delete); bu alıcıya ait geçmiş transferler etkilenmez.

## Kara liste

```bash
curl -X POST https://transfer.payven.com.tr/api/v1/recipients/abc12345-.../blacklist \
  -H "Authorization: Bearer $PAYVEN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "reason": "Sahte hesap bildirimi" }'
```

Alıcının IBAN'ı için Fraud modülüne kara liste olayı yayınlanır (senkron çağrı yoktur; Fraud modülü kuruluysa olayı kuyruktan işler). Yanıt `true` döner.

## Hata response'ları

| HTTP | `code` | Anlam |
|---|---|---|
| `404` | `resource_not_found` | `id` ya da `bank_id` bulunamadı / pasif banka |
| `422` | `validation_failed` | Eksik / format hatalı alan |
| `422` | `PV_RECIPIENT_BLACKLIST_FAILED` | Kara liste talebi oluşturulamadı |
| `403` | `forbidden` | `CanManageRecipients` izni yok |
