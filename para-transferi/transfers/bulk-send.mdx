---
title: "Bankaya Gönder / Yeniden Gönder"
description: "Başarısız (failed) transferi bilinçli olarak yeniden gönderme. Normal akışta onaylanan transfer otomatik gönderilir."
---

<Info>
**Normal akışta bu uca ihtiyacınız yoktur.** [Onaylanan](/para-transferi/transfers/bulk-approve)
transfer gönderim kuyruğuna alınır ve otomatik olarak bankaya iletilir. `bulk/send`, **`failed`**
durumdaki bir transferi sizin açık kararınızla yeniden göndermek için kullanılır.
</Info>

## Endpoint

```http
POST /api/v1/transfers/bulk/send
```

**Yetki:** transfer gönderme izni (`transfer-admin`).

## Hangi durumlar gönderilebilir?

| Durum | Gönderilebilir mi? |
|---|---|
| `failed` | **Evet** — bankanın kesin reddi ya da transferin bankaya hiç gidemediği (ör. banka oturumu alınamadı) durum. Yeniden göndermeden önce `error_code` / `provider_error_code`'u inceleyin |
| `approved` | Evet, ancak gerekmez — kuyruk zaten gönderir |
| `processing` | **Hayır.** Banka transferi işlemiş olabilir; sonuç otomatik ya da operatörce kesinleşir |
| `delivered`, `completed`, `refunded` | Hayır |
| `pending`, `rejected`, `awaiting_funds` | Hayır — önce onay gerekir |

<Warning>
**`processing` transferi asla yeniden göndermeyin** (yeni `external_id` ile yeniden oluşturarak da).
Banka yanıt vermediğinde (zaman aşımı) transfer `failed` yazılmaz, `processing`'te kalır; çünkü banka
ilk isteği işlemiş olabilir ve ikinci gönderim aynı alıcıya ikinci kez para çıkarır. Sonuç banka
sorgusu, banka bildirimi ya da operatör kararıyla kesinleşir ve `completed` / `failed` webhook'u gelir.
</Warning>

## İstek

```bash
curl -X POST https://transfer.payven.com.tr/api/v1/transfers/bulk/send \
  -H "Authorization: Bearer $PAYVEN_TOKEN" \
  -H "Idempotency-Key: payroll-2026-05-01-resend-1" \
  -H "Content-Type: application/json" \
  -d '{
    "transfers": [
      { "transfer_id": "8e3f5c12-9a7b-4c8d-bc4e-2c963f66afa6", "notes": "Alıcı IBAN düzeltildi, yeniden gönderim" }
    ]
  }'
```

| Alan | Tip | Zorunluluk | Açıklama |
|---|---|---|---|
| `transfers[]` | array | Zorunlu | Gönderilecek transferler |
| `transfers[].transfer_id` | UUID | Zorunlu | Transfer kimliği |
| `transfers[].notes` | string | Opsiyonel | Denetim notu |

## Yanıt

```http
HTTP/1.1 200 OK
Content-Type: application/json
```

```json
{
  "total_requested":   3,
  "successfully_sent": 1,
  "failed":            1,
  "outcome_unknown":   1,
  "results": [
    {
      "transfer_id":         "8e3f5c12-9a7b-4c8d-bc4e-2c963f66afa6",
      "is_success":          true,
      "message":             "Transfer başarıyla işleme gönderildi.",
      "error_code":          null,
      "provider_error_code": null
    },
    {
      "transfer_id":         "9f3d2b8e-...",
      "is_success":          false,
      "message":             "Banka oturumu alınamadı; transfer bankaya gönderilmedi.",
      "error_code":          "PV_CONNECTOR_TOKEN_UNAVAILABLE",
      "provider_error_code": "PV_CONNECTOR_TOKEN_UNAVAILABLE"
    },
    {
      "transfer_id":         "a1b2c3d4-...",
      "is_success":          false,
      "message":             "Banka yanıtı alınamadı; transferin sonucu bankayla eşitlenerek kesinleşecek. Yeniden göndermeyin.",
      "error_code":          "PV_TRANSFER_OUTCOME_UNKNOWN",
      "provider_error_code": "PV_CONNECTOR_NO_RESPONSE"
    }
  ]
}
```

| Alan | Açıklama |
|---|---|
| `total_requested` | İstekteki transfer sayısı |
| `successfully_sent` | Bankaya iletilip olumlu yanıt alınan kalem sayısı |
| `failed` | Gönderilemeyen ya da bankanın reddettiği kalem sayısı |
| `outcome_unknown` | Bankaya gönderilen ama **yanıt alınamayan** kalem sayısı — bu transferler `processing`'te kalır |
| `results[]` | Kalem başına sonuç: `is_success`, `message`, `error_code` (Payven kodu — kararınızı buna dayandırın), `provider_error_code` (bankanın ham kodu — destek talebinde paylaşın) |

### `PV_TRANSFER_OUTCOME_UNKNOWN`

Bir kalemde `error_code: "PV_TRANSFER_OUTCOME_UNKNOWN"` görürseniz banka yanıt vermemiştir:

- Transfer **`processing`** durumunda kalır; **başarısız sayılmaz**.
- **Yeniden göndermeyin.** Sonuç otomatik olarak (banka sorgusu / banka bildirimi) ya da operatörce kesinleşir.
- `para-transferi.transfer.outcome_unknown` webhook'u gelir; kesin sonuç ayrıca `para-transferi.transfer.completed` ya da `para-transferi.transfer.failed` olarak bildirilir.

Örnek mesaj ve kodlar temsilidir; banka redlerinde `provider_error_code` bankanın ham kodunu taşır ve
bankaya göre değişir — bkz. [Hata Kodları](/para-transferi/errors/overview).

## Asenkron sonuç

`is_success: true` kalemin **bankaya iletildiğini** gösterir; kesin sonuç her zaman webhook ile gelir:

| Webhook olayı | Anlam |
|---|---|
| `para-transferi.transfer.completed` | Transfer gerçekleşti |
| `para-transferi.transfer.delivered` | Banka aldı; kesin sonuç sonra (`completed` ya da `failed`) |
| `para-transferi.transfer.failed` | Bankanın kesin reddi |
| `para-transferi.transfer.outcome_unknown` | Banka yanıt vermedi; bekleyin |

Webhook gelmezse `GET /api/v1/transfers?external_id=` ya da `?request_id=` ile sorgulayın — bkz.
[Transfer Listesi](/para-transferi/inquiries/transfer-list).

## Hata response'ları

| HTTP | `code` | Anlam |
|---|---|---|
| `422` | `validation_failed` | `transfers[]` boş veya kimlik formatı geçersiz |
| `403` | `forbidden` | Gönderim izni yok |
| `409` | `idempotency_key_in_use` | Aynı `Idempotency-Key` farklı gövde için kullanılmış |

Kalem bazındaki banka redleri HTTP hatası olarak değil, `200` yanıtın `results[]` dizisinde döner.
Hata yanıtı RFC 9457 problem+json. Detay: [Hata Yönetimi](/documentation/concepts/errors).
