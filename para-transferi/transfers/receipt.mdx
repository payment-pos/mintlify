---
title: "Dekont (Makbuz) İndirme"
description: "Transferin banka dekontunu PDF/Base64 olarak ve Payven makbuzunu alın."
---

Bir transfer için iki belge alınabilir:

| Belge | Uç | Nedir |
|---|---|---|
| **Banka dekontu** | `GET /transfers/{id}/receipt/download`, `/receipt/base64` | Bankanın ürettiği resmi dekont (PDF) |
| **Payven makbuzu** | `GET /receipts/transfer/{id}` (+ `/html`, `/send`) | Her bankada aynı tasarımla, işyerinin kimliğiyle ve anlaşılır dille hazırlanan makbuz |

İki belge **aynı durumlarda** vardır: `delivered`, `completed`, `refunded`. Transferin `receipt_available`
alanı bu kararı verir; durum listesini kendi tarafınızda tutmayın.

## Banka dekontu

```http
GET /api/v1/transfers/{id}/receipt/download   # PDF dosyası (binary)
GET /api/v1/transfers/{id}/receipt/base64     # Base64-encoded string
```

**Yetki:** `CanViewTransfers`.

### PDF dosyası olarak indirme

```bash
curl https://transfer.payven.com.tr/api/v1/transfers/8e3f5c12-9a7b-4c8d-bc4e-2c963f66afa6/receipt/download \
  -H "Authorization: Bearer $PAYVEN_TOKEN" \
  -o makbuz.pdf
```

Yanıt:

```http
HTTP/1.1 200 OK
Content-Type: application/pdf
Content-Disposition: attachment; filename="PAYVEN_8e3f5c12-9a7b-4c8d-bc4e-2c963f66afa6.pdf"
```

### Base64 olarak alma

E-posta eki, mobil uygulama görüntüleme veya başka bir sistemden yükleme yaparken doğrudan Base64 string almak daha pratiktir:

```bash
curl https://transfer.payven.com.tr/api/v1/transfers/8e3f5c12-9a7b-4c8d-bc4e-2c963f66afa6/receipt/base64 \
  -H "Authorization: Bearer $PAYVEN_TOKEN"
```

Yanıt **ham Base64 string**'dir (JSON nesnesi değil):

```json
"JVBERi0xLjQKJYCBgoMKMSAwIG9iago8PA..."
```

Tipik kullanım — Node.js ile e-posta eki:

```javascript
const res = await fetch(
  `https://transfer.payven.com.tr/api/v1/transfers/${transferId}/receipt/base64`,
  { headers: { Authorization: `Bearer ${token}` } }
);
const content = await res.json(); // ham base64 string

await mailer.send({
  to: customer.email,
  subject: "Transfer dekontunuz",
  attachments: [{ filename: `dekont-${transferId}.pdf`, content, encoding: "base64" }],
});
```

### Hangi durumlarda mevcut?

| Transfer durumu | Dekont alınabilir mi? |
|---|---|
| `pending`, `awaiting_funds`, `approved`, `processing`, `failed`, `rejected` | Hayır — `409 PV_RECEIPT_NOT_AVAILABLE` |
| `delivered` | Evet; bazı bankalar dekontu henüz üretmemiş olabilir (`422 PV_RECEIPT_GENERATION_FAILED`) |
| `completed`, `refunded` | Evet |

Test modunda üretilen transferler için bankaya gidilmez; dekont Payven tarafından **TEST** işaretiyle
üretilir (bkz. [Test Modu](/para-transferi/sandbox)).

## Payven makbuzu

```http
GET  /api/v1/receipts/transfer/{id}         # Yapılandırılmış makbuz (JSON)
GET  /api/v1/receipts/transfer/{id}/html    # Yazdırılabilir HTML
POST /api/v1/receipts/transfer/{id}/send    # E-posta / SMS ile gönderim
```

**Yetki:** `CanViewTransfers`. Makbuz numarası, tutar (`amount` kuruş), `occurred_at`, düzenleyen (işyeri)
bilgisi, alıcı/gönderici bölümleri ve `is_test` bayrağını içerir.

```bash
curl -X POST https://transfer.payven.com.tr/api/v1/receipts/transfer/8e3f5c12-.../send \
  -H "Authorization: Bearer $PAYVEN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "channel": "email", "recipient": "ahmet@example.com" }'
```

`channel`: `email` ya da `sms`. Yanıt `channel`, `masked_recipient`, `delivered`, `simulated`, `message`
alanlarını taşır; test modundaki işlemin makbuzu dışarı gönderilmez (`simulated: true`).

## Hata response'ları

| HTTP | `code` | Anlam |
|---|---|---|
| `404` | `PV_TRANSFER_NOT_FOUND` | `id` bulunamadı ya da başka bayiye ait |
| `409` | `PV_RECEIPT_NOT_AVAILABLE` | Transferin mevcut durumunda dekont yok |
| `422` | `PV_RECEIPT_GENERATION_FAILED` | Banka dekontu döndüremedi — `message` alanında detay bulunur |
| `403` | `forbidden` | Yetki yok |

Banka dekontu henüz üretmediyse kısa süre sonra tekrar deneyin. Banka tarafı 24 saatte üretmediyse [destek talebi](/resources/support) açın.
