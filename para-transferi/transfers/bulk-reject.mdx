---
title: "Transfer Reddet (Reject)"
description: "Henüz bankaya gönderilmemiş transferleri reddetme — alternatif 2. adım."
---

Reject, 4-göz akışında **onay yerine** uygulanan alternatif aksiyondur. Reddedilen transfer `rejected`
durumuna geçer; bankaya hiçbir istek gönderilmez ve hesaplarınızdan para çekilmez.

## Endpoint

```http
POST /api/v1/transfers/bulk/reject
```

**Yetki:** transfer onaylama izni (`transfer-admin`; onay yetkisiyle aynı).

## Hangi durumlar reddedilebilir?

| Durum | Reddedilebilir mi? |
|---|---|
| `pending`, `approved`, `awaiting_funds` | Evet — henüz bankaya gitmedi |
| `processing`, `delivered`, `completed`, `failed`, `refunded` | Hayır |

`approved` transfer gönderim kuyruğundadır; o an bankaya gönderilmekteyse ret o kalem için başarısız
döner (`error_code: "PV_TRANSFER_INVALID_STATE"`).

## Ne zaman kullanılır?

| Senaryo | Aksiyon |
|---|---|
| Yanlış kaynak hesap seçildi | Reject + yeni transfer |
| Hatalı tutar veya alıcı | Reject + yeni transfer |
| 4-göz onay süreci başarısız (onaylayıcı itiraz etti) | Reject |
| Toplu transfer içinde bir kalem hatalı, kalanı temiz | Sadece hatalıyı reject + yeni transfer |

<Note>
**Yeni transfer yeni `external_id` ister.** Reddedilen transfer `external_id`'sini korur; aynı
referansla yeniden oluşturma `409 PV_TRANSFER_EXTERNAL_ID_DUPLICATE` döner. Reddedilen transfer
ayrıca `bulk/approve` ile yeniden onaylanabilir.
</Note>

<Note>
**Reject ≠ İade.** Bankaya gönderilmiş bir transfer reddedilemez. Gönderilmiş transferin geri alınması
iade akışıyla yapılır (`para-transferi.transfer.refunded`).
</Note>

## İstek

```bash
curl -X POST https://transfer.payven.com.tr/api/v1/transfers/bulk/reject \
  -H "Authorization: Bearer $PAYVEN_TOKEN" \
  -H "Idempotency-Key: payroll-2026-05-01-reject" \
  -H "Content-Type: application/json" \
  -d '{
    "transfers": [
      { "transfer_id": "8e3f5c12-9a7b-4c8d-bc4e-2c963f66afa6", "rejection_reason": "Yanlış kaynak hesap seçildi" },
      { "transfer_id": "9f3d2b8e-..." }
    ]
  }'
```

| Alan | Tip | Zorunluluk | Açıklama |
|---|---|---|---|
| `transfers[]` | array | Zorunlu | Reddedilecek transferler |
| `transfers[].transfer_id` | UUID | Zorunlu | Transfer kimliği |
| `transfers[].rejection_reason` | string | Opsiyonel | Red gerekçesi — denetim kaydında saklanır ve webhook'un `message` alanında döner |

## Yanıt

```http
HTTP/1.1 200 OK
Content-Type: application/json
```

```json
{
  "total_requested":       2,
  "successfully_rejected": 1,
  "failed":                1,
  "results": [
    {
      "transfer_id":         "8e3f5c12-9a7b-4c8d-bc4e-2c963f66afa6",
      "is_success":          true,
      "message":             "Transfer rejected successfully.",
      "error_code":          null,
      "provider_error_code": null
    },
    {
      "transfer_id":         "9f3d2b8e-...",
      "is_success":          false,
      "message":             "Transfer cannot be rejected. Current status: Processing",
      "error_code":          null,
      "provider_error_code": null
    }
  ]
}
```

| Alan | Açıklama |
|---|---|
| `total_requested` | İstekteki transfer sayısı |
| `successfully_rejected` | Reddedilen transfer sayısı |
| `failed` | Reddedilemeyen transfer sayısı |
| `results[]` | Kalem başına sonuç: `is_success`, `message`, `error_code`, `provider_error_code` |

Bazı kalemler reddedilemese de yanıt `200 OK` döner; her kalemin akıbeti `results[]` içindedir.

## Hata response'ları

| HTTP | `code` | Anlam |
|---|---|---|
| `422` | `validation_failed` | `transfers[]` boş veya kimlik formatı geçersiz |
| `403` | `forbidden` | Yetki yok |
| `409` | `idempotency_key_in_use` | Aynı `Idempotency-Key` farklı gövde için kullanılmış |

Hata yanıtı RFC 9457 problem+json.

## Webhook olayı

Reddedilen her transfer için `para-transferi.transfer.rejected` webhook olayı yayınlanır
(`status: "rejected"`, red gerekçesi `message` alanında). Para hiç hareket etmediği için bakiye etkisi
yoktur. Ayrıntı: [Olay Kataloğu](/para-transferi/webhooks/events).
