---
title: "2. Adım — Transfer Onayla"
description: "Pending transferleri yetkili kullanıcı ile onaylama — onaylanan transfer otomatik olarak bankaya gönderilir."
---

Approve, 4-göz akışının ikinci adımıdır. **`pending`** durumdaki transferleri yetkili kullanıcı onaylar.
Onaylanan transfer gönderim kuyruğuna alınır ve **otomatik olarak bankaya gönderilir** — normal akışta
ayrıca [`bulk/send`](/para-transferi/transfers/bulk-send) çağırmanız gerekmez.

## Endpoint

```http
POST /api/v1/transfers/bulk/approve
```

**Yetki:** transfer onaylama izni (`transfer-admin`).

<Note>
**Aynı kimlik oluşturup onaylayabilir mi?** Organizasyonunuzda ayrı onaylayıcı (4-göz) kuralı açıksa
transferi oluşturan kullanıcı / API anahtarı onu onaylayamaz; o kalem `results[]` içinde
`is_success: false` döner. Kural kapalıysa aynı kimlik onaylayabilir. Ayar Payven tarafında bayi
bazında yapılır.
</Note>

Toplu transfer paketinden (Excel, `bulk_transfer_batch_id` dolu) gelen kalemler tek tek onaylanamaz
(`error_code: "PV_BULK_ITEM_REQUIRES_BATCH_APPROVAL"`); paket kendi onay ucuyla onaylanır.

## İstek

```bash
curl -X POST https://transfer.payven.com.tr/api/v1/transfers/bulk/approve \
  -H "Authorization: Bearer $PAYVEN_TOKEN" \
  -H "Idempotency-Key: payroll-2026-05-01-approve" \
  -H "Content-Type: application/json" \
  -d '{
    "transfers": [
      { "transfer_id": "8e3f5c12-9a7b-4c8d-bc4e-2c963f66afa6", "approval_note": "Mayıs maaşları — finans onayı" },
      { "transfer_id": "9f3d2b8e-..." }
    ]
  }'
```

| Alan | Tip | Zorunluluk | Açıklama |
|---|---|---|---|
| `transfers[]` | array | Zorunlu | Onaylanacak transferler |
| `transfers[].transfer_id` | UUID | Zorunlu | Transfer kimliği |
| `transfers[].connector_account_id` | UUID | Koşullu | Gönderici hesap. Oluştururken hesap vermediyseniz (talep) **zorunlu**; verdiyseniz boş bırakın |
| `transfers[].approval_note` | string | Opsiyonel | Onay notu (denetim kaydında saklanır) |

## Yanıt

```http
HTTP/1.1 200 OK
Content-Type: application/json
```

```json
{
  "total_requested":       2,
  "successfully_approved": 1,
  "failed":                1,
  "results": [
    {
      "transfer_id":         "8e3f5c12-9a7b-4c8d-bc4e-2c963f66afa6",
      "is_success":          true,
      "message":             "Transfer approved successfully.",
      "error_code":          null,
      "provider_error_code": null
    },
    {
      "transfer_id":         "9f3d2b8e-...",
      "is_success":          false,
      "message":             "Transfer cannot be approved. Current status: Completed",
      "error_code":          null,
      "provider_error_code": null
    }
  ]
}
```

| Alan | Açıklama |
|---|---|
| `total_requested` | İstekteki transfer sayısı |
| `successfully_approved` | Onaylanan transfer sayısı |
| `failed` | Onaylanamayan transfer sayısı |
| `results[]` | Kalem başına sonuç: `is_success`, `message`, `error_code` (Payven kodu), `provider_error_code` |

Toplu onayda bazı kalemler onaylanamayabilir; yanıt yine `200 OK` döner, her kalemin akıbeti
`results[]` içindedir. Karar için `is_success`'i kullanın; `error_code` bazı ret nedenlerinde
(ör. durum uygun değil, 4-göz) boş gelebilir, açıklama `message` alanındadır.

## Onaydan sonra

| Durum | Anlam |
|---|---|
| `approved` | Gönderim kuyruğunda; kısa süre içinde `processing` olur |
| `awaiting_funds` | Bayinin talebi hakedişinden karşılanacak; fon ayrılınca gönderilir |

Sonucu webhook ile dinleyin (`para-transferi.transfer.approved`, ardından `completed` / `delivered` /
`failed` / `outcome_unknown`) — bkz. [Olay Kataloğu](/para-transferi/webhooks/events).

## Hata response'ları

| HTTP | `code` | Anlam |
|---|---|---|
| `422` | `validation_failed` | `transfers[]` boş veya kimlik formatı geçersiz |
| `403` | `forbidden` | Onay izni yok |
| `409` | `idempotency_key_in_use` | Aynı `Idempotency-Key` farklı gövde için kullanılmış |

Hata yanıtı RFC 9457 problem+json.
