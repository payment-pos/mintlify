Bir transferin **mevcut** durumunu, durum geçişlerini ve webhook teslim denemelerini çekmek için kullanılır.

## Endpoint

```http
GET /api/v1/transfers/{id}
```

`id` parametresi UUID formatındadır — `POST /transfers/bulk/create` yanıtında dönen `transfer_id` ya da `GET /transfers?external_id=` ile bulunan kaydın `id`'si.

**Yetki:** `CanViewTransfers`.

## İstek

```bash
curl https://transfer.payven.com.tr/api/v1/transfers/8e3f5c12-9a7b-4c8d-bc4e-2c963f66afa6 \
  -H "Authorization: Bearer $PAYVEN_TOKEN"
```

## Yanıt

[Transfer Objesi](/para-transferi/transfer-object) döner; liste yanıtından farkı `events`, `webhook_deliveries`, `channel_suggestions` ve (parçalı ödemede) `split_group` alanlarının dolu gelmesidir:

```json
{
  "id":                        "8e3f5c12-9a7b-4c8d-bc4e-2c963f66afa6",
  "external_id":               "PAYROLL-001",
  "request_id":                "PAYROLL-2026-05",
  "status":                    "completed",
  "amount":                    1500000,
  "currency":                  "try",
  "request_transfer_type":     "fast",
  "success_transfer_type":     "fast",
  "receipt_no":                "TRF-20260503-0001",
  "receipt_available":         true,
  "message":                   "Transfer başarılı",
  "error_code":                null,
  "provider_error_code":       null,

  "receiver_account": {
    "id":          "11111111-2222-3333-4444-555555555555",
    "holder_name": "Ahmet Yılmaz",
    "iban":        "TR330006100519786457841326",
    "bank_name":   "Akbank",
    "bank_code":   "00046"
  },

  "events": [
    { "id": "e4…", "status": "completed",  "event_type": "BankStatusSync", "created_at": "2026-05-03T12:35:00.000+03:00" },
    { "id": "e3…", "status": "processing", "event_type": null,                "created_at": "2026-05-03T12:34:58.000+03:00" },
    { "id": "e2…", "status": "approved",   "event_type": "TransferApproved",  "created_at": "2026-05-03T12:34:55.000+03:00" }
  ],

  "webhook_deliveries": [
    {
      "id":             "b1…",
      "url":            "https://example.com/webhooks/payven-transfers",
      "event":          "para-transferi.transfer.completed",
      "status":         "delivered",
      "attempt_count":  1,
      "response_code":  200,

      "next_retry_at":  null
    }
  ]

```

| Alan | Açıklama |
|---|---|
| `events[]` | Durum geçişleri, yeni → eski: `status`, `event_type`, `created_at` |
| `webhook_deliveries[]` | Bu transfer için yapılan teslim denemeleri; `status`: `pending` (yeniden deneme planlı), `delivered`, `failed` (deneme hakkı bitti) |
| `channel_suggestions[]` | FAST ile gönderilip başarısız olan transfer için öneriler (`kind`, `transfer_type`, `split_count`, `max_part_amount`, `fast_limit`) |

## İşlem geçmişi

Kullanıcı eylemlerini ve banka iletişimini kronolojik zaman çizelgesi olarak almak için:

```http
GET /api/v1/transfers/{id}/history
```

```json
[
  {
    "occurred_at": "2026-05-03T12:00:00.123+03:00",
    "action":      "Transfer oluşturuldu",
    "source":      "user",
    "actor":       "a1b2c3d4-...",
    "details":     null,
    "status_from": null,
    "status_to":   "Onay Bekliyor"
  },
  {
    "occurred_at": "2026-05-03T12:35:00.000+03:00",
    "action":      "Durum: Tamamlandı",
    "source":      "bank",
    "actor":       null,
    "details":     null,
    "status_from": "İşleniyor",
    "status_to":   "Tamamlandı"
  }
]
```

| Alan | Açıklama |
|---|---|
| `occurred_at` | Olayın zamanı (`+03:00`) |
| `action` | Türkçe okunabilir eylem etiketi |
| `source` | `user` (kullanıcı eylemi), `system` (sistem), `bank` (banka iletişimi) |
| `actor` | Eylemi tetikleyen kimlik (varsa) |
| `details` | Serbest açıklama (istek/yanıt özeti, değişen alanlar) |
| `status_from` / `status_to` | Durum değiştiyse önceki / yeni durumun **Türkçe etiketi** (ekran gösterimi içindir; makine kararı için `status` alanını ve webhook'ları kullanın) |

## Başarısız transferin sorgusu

Başarısız transfer (`status: "failed"`) sorgulandığında yanıt **`200 OK`** döner; hata detayları alanlarda taşınır:

```json
{
  "id":                  "8e3f5c12-...",
  "status":              "failed",
  "error_code":          "PV_TRANSFER_DECLINED",
  "provider_error_code": "01",
  "message":             "Banka transferi reddetti.",
  "retry_count":         0
}
```

`error_code` kararınızın dayanağı, `provider_error_code` bankanın ham kodudur (destek bunu arar).
Kod listesi: [Hata Kodları](/para-transferi/errors/overview).

## Metadata güncelleme

Transferin `metadata` alanı durumdan bağımsız olarak güncellenebilir; tutar, alıcı ve duruma dokunmaz.
Gönderilen anahtar yazılır, gönderilmeyen korunur, boş değerli anahtar silinir:

```bash
curl -X PATCH https://transfer.payven.com.tr/api/v1/transfers/8e3f5c12-... \
  -H "Authorization: Bearer $PAYVEN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "metadata": { "muhasebe_kodu": "770.01", "payroll_run": "" } }'
```

Yanıt güncel transfer detayıdır. Sınırlar: en fazla 50 anahtar, anahtar 40, değer 500 karakter.
**Yetki:** `CanCreateTransfers`.

## Tipik kullanım

- **Webhook gelmemiş bir transfer** için son durumu öğrenmek
- **Müşteri destek talebinde** geçmiş bir transferi incelemek (`history`)
- **Audit / uyumluluk** raporlamasında durum geçişlerini ekstrakt etmek
- **Banka tarafı sorununu** debug etmek (`error_code` + `provider_error_code`)

<Warning>
**Polling kullanmayın.** Yüksek hacimli senaryolarda her transfer için periyodik `GET` çağrısı yapmayın — bunun yerine [webhook](/para-transferi/webhooks/overview) entegre edin. Webhook gelmemişse İşyeri paneli › **Geliştirici › Webhook'lar** ekranından (ya da `POST /webhook-endpoints/deliveries/{id}/retry` ile) teslimi yeniden gönderebilir veya olayı `GET /events` ile çekebilirsiniz. Toplu yedek sorgu için transfer başına detay yerine `GET /transfers?request_id=` (paket) ya da `?external_id=` kullanın — bkz. [Önerilen Entegrasyon Akışı](/para-transferi/integration-guide).
</Warning>

<Note>
`processing` durumundaki transfer **yeniden gönderilmemelidir** — banka yanıt vermediğinde transfer bu
durumda kalır (`provider_error_code: "PV_CONNECTOR_NO_RESPONSE"`) ve sonucu banka sorgusu, banka
bildirimi ya da operatör kesinleştirir. Bkz. [Belirsiz Sonuç ve İade](/para-transferi/transfers/outcome-resolution).
</Note>

## Hata response'ları

| HTTP | `code` | Anlam |
|---|---|---|
| `404` | `resource_not_found` | Verilen `id` bulunamadı veya bu bayi/organizasyona ait değil |
| `403` | `forbidden` | Yetki yok |

Hata yanıtı RFC 9457 problem+json formatındadır.
