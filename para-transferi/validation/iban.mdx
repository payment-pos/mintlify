IBAN doğrulama, kullanıcının girdiği IBAN'ı **transfer oluşturmadan önce** kontrol etmek içindir. Transfer akışında **opsiyonel** bir adımdır; transfer oluştururken ve alıcı hesabı kaydederken IBAN zaten otomatik doğrulanır, ancak proaktif kullanıcı geri bildirimi için bu uç UX'i iyileştirir.

## Endpoint

IBAN doğrulama **Identity API'sinin** bir ucudur (Para Transferi API'sinde değildir):

```http
POST https://identity.payven.com.tr/api/v1/validation/iban
```

Bearer access token gerektirir; ayrı bir transfer izni aranmaz. İstek ve yanıt ayrıntıları: [Identity › IBAN Doğrulama](/identity/validation/iban).

```bash
curl -X POST https://identity.payven.com.tr/api/v1/validation/iban \
  -H "Authorization: Bearer $PAYVEN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "iban": "TR33 0006 1005 1978 6457 8413 26", "resolve": true }'
```

Yanıt `200 OK`; geçersiz IBAN da `200` ile gelir, sonucu `is_valid` belirler:

```json
{
  "is_valid":       true,
  "format_valid":   true,
  "checksum_valid": true,
  "country_code":   "TR",
  "check_digits":   "33",
  "bank_code":      "00061",
  "formatted_iban": "TR33 0006 1005 1978 6457 8413 26",
  "masked_iban":    "TR33 **** **** **** **** 1326",
  "bank":           { "id": "5e0b0f2a-...", "code": "00061", "name": "..." },
  "error_message":  null
}
```

`bank_code` TR IBAN'ının banka kısmıdır (5 haneli TCMB kodu); `resolve: true` iken `bank` alanı banka kataloğundan çözülür.

## Transfer sırasındaki doğrulama

| Nerede | Ne kontrol edilir | Sonuç |
|---|---|---|
| `POST /transfers/bulk/create` | IBAN uzunluğu + mod-97 + banka kodunun kataloğa çözülmesi (`TR` öneki yoksa eklenir) | Geçersiz IBAN'lı kalem **atlanır**; hiçbir kalem geçerli değilse `422 PV_NO_VALID_TRANSFER`. Bkz. [Geçersiz kalemler](/para-transferi/transfers/bulk-create#geçersiz-kalemler) |
| `POST /bulk-transfers/preview` ve `POST /bulk-transfers` | Satır başına uzunluk (26), mod-97, banka çözümleme | Satır `invalid` olur ve `errors[]`'te nedeni görünür |
| `POST /receiver-accounts`, `PUT /receiver-accounts/{id}` | Uzunluk + mod-97 | `422 validation_failed` |

Transfer oluşturmadaki IBAN doğrulaması organizasyon / bayi ayarıyla kapatılabilir; kapalıyken IBAN olduğu gibi bankaya iletilir ve ret kararını banka verir.

## UI entegrasyonu — debounce

IBAN alanına yazılırken her karakter için doğrulama atmayın; debounce uygulayın (örn. 500 ms, IBAN tam yazıldıktan sonra):

```javascript
let debounceTimer;
ibanInput.addEventListener("input", (e) => {
  clearTimeout(debounceTimer);
  const iban = e.target.value.replace(/\s+/g, "");
  if (iban.length < 26) {
    setBankBadge(null);
    return;
  }
  debounceTimer = setTimeout(async () => {
    const res = await fetch("/api/payven/validate-iban", {   // sunucunuz Identity'ye iletir
      method: "POST",
      body: JSON.stringify({ iban }),
    });
    const result = await res.json();
    if (result.is_valid) {
      setBankBadge(result.bank?.name);
    } else {
      setError(result.error_message);
    }
  }, 500);
});
```

Token'ı tarayıcıya koymayın; doğrulamayı kendi sunucunuz üzerinden çağırın.
