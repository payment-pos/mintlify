Payven Sanal POS, ödeme kuruluşları ve büyük platformlar için **çoklu banka entegrasyonlu** bir ödeme alma altyapısıdır. Tek bir API ile birden fazla bankaya ödeme yönlendirir, akıllı yönlendirme motoruyla başarı oranını maksimize eder.

## Hangi entegrasyonu seçmeliyim?

<Tabs>
  <Tab title="Hosted Checkout (önerilir)">
    **Sizin akış:**
    1. Sunucunuz `POST /api/v1/checkout/sessions` ile bir oturum oluşturur.
    2. Müşteriyi dönen `checkout_url`'e yönlendirirsiniz.
    3. Müşteri kart bilgilerini Payven sayfasında girer.
    4. Sonuç webhook ile size iletilir.

    **Avantajlar:** En düşük PCI-DSS yükü (SAQ-A), 3DS otomatik, taksit seçimi sayfada.

    **Uygunsa:** Çoğu B2C entegrasyonu için tercih bu olmalı.

    [Detay →](/sanal-pos/payments/hosted-checkout) · [Checkout oturumu referansı →](/sanal-pos/payments/checkout-sessions)
  </Tab>
  <Tab title="Pay-by-Link">
    **Sizin akış:**
    1. Sunucunuz `POST /api/v1/payments/order-link` ile banka barındırmalı ödeme linki üretir (kalıcı, ürünlü bağlantılar için `POST /api/v1/payment-links`).
    2. SMS, e-posta veya WhatsApp ile müşteriye gönderirsiniz.
    3. Müşteri linkten ödemeyi yapar.

    **Avantajlar:** Sıfır frontend geliştirme, çağrı merkezi senaryoları için ideal.

    [Detay →](/sanal-pos/payments/pay-by-link)
  </Tab>
  <Tab title="Direct API">
    **Sizin akış:**
    1. Kart bilgilerini kendi formunuzdan toplarsınız.
    2. Non-3D için `POST /api/v1/payments`, 3D Secure için `POST /api/v1/payments/3d/init` çağırırsınız.
    3. 3DS gerekiyorsa müşteriyi yanıttaki yönlendirmeye gönderirsiniz.
    4. Banka dönüşü Payven'e gelir, sonuç webhook ile size iletilir.

    **Avantajlar:** UI üzerinde tam kontrol.

    **Maliyet:** PCI-DSS denetim kapsamı yüksek (SAQ-D veya ROC). Yalnızca sertifikalı organizasyonlar kullanmalı.

    [Non-3D →](/sanal-pos/payments/non-3d) · [3D Secure →](/sanal-pos/payments/3d-secure)
  </Tab>
</Tabs>

Her yazma isteğinde `external_id` (sipariş kimliği) zorunludur ve çift çekimi önleyen anahtar olarak çalışır; ayrıca `Idempotency-Key` başlığı gönderin — bkz. [Kimlik Doğrulama](/sanal-pos/authentication#idempotency-key).

## Endpoint kategorileri

Tüm path'ler `/api/v1/` ön ekiyle başlar. Tam liste için: [API Referansı](/api-reference/sanal-pos). Tüm uçlar Bearer token ister.

| Kategori | Endpoint örnekleri | Sayfa |
|---|---|---|
| Ödeme oluşturma | `POST /payments`, `POST /payments/3d/init`, `POST /payments/order-link`, `POST /checkout/sessions`, `POST /payment-links` | [Non-3D](/sanal-pos/payments/non-3d), [3DS](/sanal-pos/payments/3d-secure), [Checkout](/sanal-pos/payments/checkout-sessions) |
| Ödeme aksiyonları | `POST /payments/{id}/capture`, `/refund`, `/void`, `/reconcile`, `/point-inquiry`, `/dcc/confirm`; `POST /payments/3d/complete` | [Pre-Auth](/sanal-pos/payments/pre-auth-capture), [İade](/sanal-pos/payments/refund), [İptal](/sanal-pos/payments/void) |
| Sorgulama | `GET /payments/{id}`, `GET /payments/{id}/query`, `GET /payments/{id}/history`, `GET /transactions`, `GET /transactions/{id}`, `GET /transactions/export` | [Sorgulama](/sanal-pos/inquiries/payment-detail) |
| Taksit ve BIN | `POST /installments/quote`, `POST /bins/check`, `GET /bins/{bin}` | [Taksit](/sanal-pos/payments/installment) |
| Tekrarlayan ödeme | `POST /recurring`, `GET /recurring`, `POST /recurring/{id}/cancel`, `.../installments/{index}/cancel`, `.../installments/{index}/update-amount`, `POST /recurring/{id}/update-card-expiry` | [Recurring](/sanal-pos/payments/recurring) |
| Kayıtlı kart | `GET /cards`, `GET /cards/{id}`, `DELETE /cards/{id}` | [Kayıtlı Kart](/sanal-pos/payments/saved-cards) |
| İade listesi | `GET /refunds`, `GET /refunds/{id}` | [İade](/sanal-pos/payments/refund) |
| İade / iptal talepleri | `POST /refund-requests`, `POST /refund-requests/{id}/approve\|reject`; `POST /cancellation-requests`, `.../approve\|reject` | [İade Talepleri](/sanal-pos/payments/refund-requests), [İptal Talepleri](/sanal-pos/payments/cancellation-requests) |
| Ürün ve indirim | `/products`, `/discount-codes` | [Ürünler](/sanal-pos/payments/products) |
| Pazaryeri | `GET /marketplace/splits`, `POST /marketplace/splits/{id}/approve\|hold\|release\|refund` | [Split](/sanal-pos/payments/marketplace-splits) |
| Makbuz | `GET /receipts/{source}/{id}`, `.../html`, `.../send` | [Makbuz](/sanal-pos/payments/receipts) |
| Ters ibraz | `GET /chargebacks`, `POST /chargebacks`, `PUT /chargebacks/{id}/status` | [Chargeback](/sanal-pos/reporting/chargebacks) |
| Mutabakat | `POST /reconciliations/start`, `POST /reconciliations/{id}/finalize`, `POST /reconciliations/{id}/cancel` | [Mutabakat](/sanal-pos/reconciliation/overview) |
| Belirsiz banka işlemleri | `GET /unresolved-bank-operations`, `POST /unresolved-bank-operations/{id}/resolve` | [Mutabakat yaşam döngüsü](/sanal-pos/reconciliation/lifecycle) |
| Yönlendirme kuralları | `/routing-rules`, `POST /routing-rules/resolve`, `/simple-routing-rules` | [Routing](/sanal-pos/routing/overview) |
| Konnektör | `GET /connectors`, `GET /connectors/{id}/health`, `GET /connectors/types/{code}/schema` | [Routing](/sanal-pos/routing/circuit-breaker) |
| Test kartları | `GET /test-cards`, `POST /test-cards`, `POST /test-cards/generate` | [Test Kartları](/sanal-pos/test/test-cards) |
| Webhook yönetimi | Sanal POS API'sinde değil **İşyeri API'sinde**: `POST /webhook-endpoints`, `POST /webhook-endpoints/{id}/rotate-secret`, `GET /webhook-endpoints/{id}/deliveries` | [Webhook'lar](/sanal-pos/webhooks/overview) |

Gün sonu hakediş ve çekim (payout) uçları Cüzdan servisindedir; bkz. [Raporlama](/sanal-pos/reporting/settlements).

## İşlem yaşam döngüsü

İşlem durumu `status` alanında, `TransactionStatus` değerlerinin snake_case karşılığı olarak döner. Kısmi iade, üst işlemin durumunu değiştirmez (`completed` kalır); iade ayrı iade kaydı olarak yazılır.

```mermaid
stateDiagram-v2
    [*] --> created: POST /payments
    created --> processing: bankaya gönderildi
    created --> three_d_secure_init_processing: 3DS başlatıldı
    three_d_secure_init_processing --> three_d_secure_auth_processing: banka dönüşü geldi
    three_d_secure_init_processing --> failed: 3DS reddi
    three_d_secure_init_processing --> not_completed: müşteri terk etti
    three_d_secure_auth_processing --> authorized: Pre-Auth onayı
    three_d_secure_auth_processing --> completed: Sale onayı
    three_d_secure_auth_processing --> failed: banka reddi
    processing --> authorized: Pre-Auth onayı
    processing --> completed: Sale onayı
    processing --> failed: banka reddi
    authorized --> capture_processing: capture
    capture_processing --> completed
    authorized --> canceled_processing: void
    completed --> canceled_processing: void
    canceled_processing --> canceled
    completed --> refund_processing: refund
    refund_processing --> refunded: tam iade
    refund_processing --> completed: kısmi iade
    failed --> [*]
    not_completed --> [*]
    canceled --> [*]
    refunded --> [*]
```

Tam durum tablosu ve anlamları: [Payment Objesi → Status](/sanal-pos/payment-object#status-degerleri). Her durum geçişinde oluşan webhook olayları: [Webhook Olayları](/sanal-pos/webhooks/events).
