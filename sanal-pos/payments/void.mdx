title: "İptal (Void)"
description: "Aynı gün içinde yapılmış bir ödemeyi tam tutarda iptal edin."
---

Void, ödemenin **tam tutarlı** iptalidir. İade'den (refund) farkı: iptal edilen işlem müşterinin kart ekstresinde hareket olarak kalmaz, ödeme hiç olmamış gibi kayıttan düşer.

<Note>
Bu uç **doğrudan iptal** yetkisi (`CanVoidDirectly`) ister; varsayılan olarak yalnızca `tenant-admin` rolünde açıktır. Onay akışıyla iptal için [İptal Talepleri](/sanal-pos/payments/cancellation-requests) kullanılır: talep açılır, ikinci bir kullanıcı onaylayınca iptal otomatik yürütülür.
</Note>

## Endpoint

```http
POST /api/v1/payments/{transaction_id}/void
```

## Ne zaman iptal edilebilir?

Aşağıdaki koşulların **tümü** sağlanmalıdır; aksi halde `409 VOID_NOT_ALLOWED` döner:

- İşlem `completed` (satış) veya `authorized` (ön provizyon) durumunda,
- İşlem **oluşturulduğu Türkiye takvim günü** içinde (gün dönümünden sonra iptal edilemez),
- İşlemden daha önce başarılı bir **iade yapılmamış** (kalan tutar için [iade](/sanal-pos/payments/refund) kullanın).

İşlem `three_d_secure_*`, `processing` gibi devam eden bir durumdaysa iptal edilemez; önce sonucu kesinleşmesini bekleyin. Zaten `canceled` olan işlem için tekrar gelen istek **başarılı** döner (idempotent).

## İstek

```bash
curl -X POST https://vpos.payven.com.tr/api/v1/payments/8e3f5c12-9a7b-4c8d-bc4e-2c963f66afa6/void \
  -H "Authorization: Bearer $PAYVEN_TOKEN" \
  -H "Idempotency-Key: order-1001-void" \
  -H "Content-Type: application/json" \
  -d '{
    "reason": "Stok kalmadı"
  }'
```

| Alan | Tip | Zorunluluk | Açıklama |
|---|---|---|---|
| `reason` | string | Opsiyonel | İptal sebebi (en fazla 500 karakter) |
| `extra_properties` | object | Opsiyonel | Bankaya özgü ek alanlar |

Gövde bir JSON nesnesi olmalıdır (`{}` yeterli); gövdesiz ya da bozuk JSON `400 invalid_request_body` döner.

## Başarılı yanıt

```json
{
  "transaction_id": "8e3f5c12-9a7b-4c8d-bc4e-2c963f66afa6",
  "status":         "canceled",
  "is_success":     true,
  "extra_properties": {
    "processed_at":            "2026-05-03T16:00:01.234+03:00",
    "provider_transaction_id": "VOID-9f3d2b8e",
    "receipt_id":              "RCPT-4471",
    "host_reference":          "VOID-REF-789"
  }
}
```

<Note>
İptalin ayrı bir kaydı yoktur — iptal, ödemenin **kendi** kaydını `canceled` durumuna çeker. Yanıttaki `transaction_id` hem ödemenin hem de iptalin kimliğidir; ayrı bir `refund_id` benzeri alan yoktur. Bankaya yapılan çağrı sürerken işlem kısa süre `canceled_processing` durumunda görünebilir; hata olursa önceki durumuna geri döner.
</Note>

## Void mu, refund mu?

| Kriter | Void | Refund |
|---|---|---|
| Tutar | Yalnız tam tutar | Tam veya kısmi |
| Zaman | İşlemin oluştuğu gün içinde | Gün sonrası da yapılabilir |
| Ön önkoşul | Daha önce iade yapılmamış | `completed` ve kalan tutar > 0 |
| Müşteri ekstresinde | Hareket görünmez | "İade" satırı olarak görünür |
| Ön provizyon | `authorized` işlem iptal edilebilir | Uygulanmaz |

**Pratik kural:** Aynı gün, **tam tutar** → **void**. Diğer durumlarda → [refund](/sanal-pos/payments/refund). Payven iki uç arasında otomatik geçiş yapmaz; hangisini çağıracağınıza siz karar verirsiniz.

## Pre-Auth iptali

Henüz capture edilmemiş bir ön provizyon (`authorized`) aynı uçla iptal edilerek rezervasyon serbest bırakılır. Detay: [Pre-Auth ve Capture](/sanal-pos/payments/pre-auth-capture).

## Hata yanıtları

| HTTP | `code` | Anlam |
|---|---|---|
| `404` | `PV_TRANSACTION_NOT_FOUND` | İşlem bulunamadı |
| `400` | `invalid_request_body` | Gövde okunamadı |
| `403` | `forbidden` | `CanVoidDirectly` yetkisi yok — iptal talebi açın |
| `409` | `VOID_NOT_ALLOWED` | Durum, gün sınırı ya da önceki iade nedeniyle iptal edilemez — `/refund` kullanın |
| `409` | `PV_BANK_RESULT_PENDING` | İşlemde sonucu doğrulanmayı bekleyen başka bir banka işlemi var |
| `422` | `VOID_NOT_SUPPORTED` | İşlemin geçtiği banka iptali desteklemiyor |
| `422` | `VOID_FAILED` / `VOID_EXCEPTION` | Banka iptali reddetti (`provider_error_code` bankanın ham kodu) |
| `504` | `PV_BANK_RESULT_UNKNOWN` | Banka sonucu bildirmedi; işlem doğrulanıyor — yeniden denemeyin, sonuç kesinleşince bildirilir |

Hata yanıtı RFC 9457 problem+json formatındadır. Detay: [Hata Yönetimi](/documentation/concepts/errors).

## Webhook olayları

| Olay | Açıklama |
|---|---|
| `sanalpos.void.completed` | İptal tamamlandı (işlem `canceled`) |
| `sanalpos.void.failed` | İptal bankaca reddedildi / hata |

Detay: [Webhook Olayları](/sanal-pos/webhooks/events).
