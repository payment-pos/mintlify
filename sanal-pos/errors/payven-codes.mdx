Bu sayfa Sanal POS'un kendi domain hata kodlarını listeler. Kodlar hata yanıtının `code`
alanında **katalogdaki haliyle** (büyük harf, `PV_` veya operasyon prefix'li) döner; HTTP
durum kodu tabloda belirtilmiştir. Banka tarafından gelen ham yanıt kodu ayrıca
`provider_error_code` alanında taşınır — detay: [Banka Yanıt Kodları](/sanal-pos/errors/bank-codes).

## Genel ödeme akışı

| Kod | HTTP | Anlam |
|---|---|---|
| `PV_INSUFFICIENT_FUNDS` | 422 | Bakiye yetersiz |
| `PV_CARD_EXPIRED` | 422 | Kartın son kullanma tarihi geçmiş |
| `PV_INVALID_CARD` | 422 | Geçersiz kart |
| `PV_INVALID_CVV` | 422 | Geçersiz CVV |
| `PV_CVV_REQUIRED` | 422 | CVV zorunlu (bayi banka profili `RequireCvv` açık) |
| `PV_INVALID_CARD_NUMBER` | 422 | Geçersiz kart numarası (uzunluk / Luhn). Bu doğrulama kapatılabilir — bkz. aşağıdaki not. |
| `PV_INVALID_CARD_EXPIRY` | 422 | Kart son kullanma tarihi geçersiz |
| `PV_INVALID_CARD_HOLDER` | 422 | Geçersiz kart sahibi bilgisi |
| `PV_CARD_DATA_MISSING` | 422 | Kart verisi eksik |
| `PV_INVALID_AMOUNT` | 422 | Geçersiz tutar (negatif, sıfır) |
| `PV_INVALID_CURRENCY` | 422 | Geçersiz para birimi |
| `PV_BANK_DECLINED` | 422 | Banka işlemi reddetti — `provider_error_code` daha spesifik bilgi taşır |
| `PV_DO_NOT_HONOR` | 422 | Banka işleme izin vermedi (do not honor, banka kodu 05) |
| `PV_LIMIT_EXCEEDED` | 422 | İşlem limiti aşıldı |
| `PV_FRAUD_SUSPECTED` | 422 | İşlem güvenlik nedeniyle reddedildi |
| `PV_BIN_RESTRICTED` | 422 | Kart (BIN) bu işlem için kısıtlı |
| `PV_DUPLICATE_ORDER` | 409 | Bu sipariş (`external_id`) zaten işlenmiş |
| `PV_ORDER_AMOUNT_MISMATCH` | 422 | Bu sipariş numarası farklı bir tutarla zaten kullanılmış |
| `PV_PAYMENT_FAILED` | 422 | Ödeme işlemi başarısız (genel) |
| `PV_PAYMENT_EXCEPTION` | 422 | Ödeme sırasında beklenmeyen hata |
| `PV_NON_3D_NOT_ALLOWED` | 422 | Non-3D ödeme bu bayi için kapalı |
| `PV_TIMEOUT` | 504 | İşlem zaman aşımına uğradı |
| `PV_SYSTEM_ERROR` | 500 | Sistem hatası |
| `PV_CONFIG_ERROR` | 500 | Yapılandırma hatası (konnektör konfigürasyonu hatalı/eksik) |
| `PV_UNSUPPORTED_OPERATION` | 422 | Desteklenmeyen işlem |
| `PV_UNKNOWN` | 422 | Eşlenmemiş hata — destek talebine açın |


<Note>
**Kart numarası doğrulaması kapatılabilir.** Varsayılan olarak Payven, kartı bankaya göndermeden
önce numara uzunluğunu ve Luhn kontrolünü doğrular; geçersizse `PV_INVALID_CARD_NUMBER` döner.
Kart kontrolünü kendi tarafında yapan bayiler için bu doğrulama kapatılabilir — bu durumda kart
olduğu gibi bankaya gider ve kararı banka verir (yanıtta Payven kodu yerine bankanın kendi kodu
görünür). Ayar bayi veya tenant bazında yönetilir; talep için müşteri başarısı ekibine ulaşın.

Kapalıyken de reddedilenler: **boş** kart numarası ve **maskeli** kart numarası
(`PV_MASKED_CARD_NUMBER` — `411111****1111` gibi girdiler bir entegrasyon hatasıdır). Son
kullanma tarihi ve CVV kontrolleri bu ayardan etkilenmez.
</Note>

## Generic / HTTP kodları

Aşağıdaki kodlar Payven ortak HTTP altyapısı tarafından üretilir; spesifik bir domain kodu
yoksa fallback olarak kullanılır. Bu kodlar **lowercase snake_case** formatındadır.

| HTTP | `code` | Anlam |
|---|---|---|
| `400` | `bad_request` | Genel istek hatası |
| `401` | `unauthorized` | Token eksik / geçersiz |
| `403` | `forbidden` | Yetki yok |
| `404` | `resource_not_found` | Generic kaynak bulunamadı |
| `409` | `conflict` | Generic çakışma |
| `409` | `invalid_state` | Kaynak bu işlem için uygun durumda değil |
| `422` | `validation_failed` | Validasyon kuralı ihlali (`errors` alanında alan-bazlı detay) |
| `429` | `rate_limit_exceeded` | İstek limiti aşıldı |
| `500` | `internal_server_error` | Sunucu hatası |

## Bilinmeyen kod

`PV_UNKNOWN` — konnektörden gelen kod Payven eşleme tablosunda yok. Bu durumlarda ham banka
kodu `provider_error_code`, ham mesaj `detail` alanında bulunur. Lütfen `correlation_id` ile
birlikte [destek ekibimize](/resources/support) yazın — eşleme tablosunu güncelleyebiliriz.
